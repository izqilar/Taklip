### 运行方式
```bash
# 1. 起依赖（Docker）：h5design-postgres / h5design-redis
# 2. 起后端 + 运营端
pnpm --filter @h5design/server start
pnpm --filter @h5design/admin dev
# 3. 安装并跑 E2E
pnpm --filter @h5design/admin add -D @playwright/test
pnpm --filter @h5design/admin exec playwright install chromium
pnpm --filter @h5design/admin exec playwright test
```

### 2026-08-28 实跑核验（诚实记录）
- **工具链**：已装 `@playwright/test`（devDep，当前 1.62.1）；`playwright test --list` 11 用例全部可解析（脚手架编译通过）。
- **浏览器修订号坑**：1.62.1 要求 chromium **v1234**，但本沙箱无 playwright CDN 网络（下载 v1234 卡死），仅有缓存 `chromium-1228`（`C:\Users\Administrator\AppData\Local\ms-playwright\chromium-1228`）。正式环境用 `playwright install chromium` 装 v1234 即可。
- **用缓存 v1228 实跑验证**：chromium 成功启动 → vite 起 `:5174` → 打开 `/login` → 填手机号/密码 → 提交。首版用例在 `getByRole('button', {name:'登录'})` 处超时——根因：antd 登录按钮 accessible name 实际为 **「登 录」（含空格）**，精确匹配失败。**已修**：`admin.spec.ts` `login()` 改用 `page.locator('button[type="submit"]')`（稳健）。
- **修复后复跑**：提交按钮点击成功，随后 `waitForURL('**/dashboard')` 超时——失败点已隔离到 **后端 `:3000` 当前 DOWN**（登录 POST 不可达），与脚手架/浏览器无关。后端+Docker 就绪后即可完整跑通 §14 全部 11 项。
- **结论**：E2E 脚手架与选择器已就绪；真实全量跑通依赖后端(PG/Redis) + 运营端 dev server 同时在线。本环境仅验证到「浏览器+dev server+登录交互」一层。
