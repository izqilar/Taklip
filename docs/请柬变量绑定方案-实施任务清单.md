## 2. S1 · deriveColumnsFromRecords 兜底（前置必须）

**目标**：解除 `columnDefs` 为空导致的硬阻塞 + 静默丢弃映射。让 43% 有真实数据键却无表头的名单也能正确导出可选列。

| 项 | 内容 |
|---|---|
| **阶段** | **MVP（绝对前置）** |
| **依赖** | 无 |

### 涉及文件与行号（已确认）

| # | 文件 | 行号 | 现状 |
|---|---|---|---|
| 1 | `apps/server/src/invitation/invitation.service.ts` | `getHealth` 入口 `:1161`；列定义取用 `:1169`；`guestRecord.findMany` 取行 `:1201` | `const defs = (list?.columnDefs as unknown as GuestFieldDef[] | undefined) ?? [];` —— 无兜底；且取 `rows` 在 `defs` 之后，顺序需调整 |
| 2 | 同上 | `saveMapping` `:1376`；列定义取用 `:1382` | `const defs = (list?.columnDefs ...) ?? [];` —— 同病 |
| 3 | `packages/core/src/guest-fields.ts` | `deriveColumnsFromRecords` `:104`（签名 `(rows: {data?: Record<string,string|null>|null}[]|null|undefined) => GuestFieldDef[]`）；`toColumnDefs` `:89` | **已存在，直接复用**，无需新增 |
| 4 | `apps/server/src/invitation/invitation.service.ts` | `import` 区（文件顶部，约 `:13` 附近已有 `guest-fields` 引用） | 需补 `import { deriveColumnsFromRecords } from '@h5design/core'` 或既有 `@h5design/core` 路径 |

### 具体改法描述（只描述不修改）

- **`getHealth`**：将 `:1201` 的 `guestRecord.findMany` 上提到 `:1169` 之前（仍按 `recWhere` 选子集或全量；建议 `take: 200` 限流）；将 `:1169` 改为：
  `const defs = (list?.columnDefs && list.columnDefs.length ? (list.columnDefs as GuestFieldDef[]) : deriveColumnsFromRecords(rows)) as GuestFieldDef[];`
  即：`columnDefs` 非空用原值，为空时由 `deriveColumnsFromRecords(rows)` 从真实记录键推导兜底。`listKeys`(`:1170`) 随之自动恢复正确。
- **`saveMapping`**：将 `:1382` 同法改为兜底逻辑（`cleaned` 的键侧校验 `listKeys.has(target)` 因此能命中真实字段）。
- 两处均**复用 core 既有函数**，不新写推导逻辑。

### 依赖任务
无。

### 验收断言（机器可验证）

1. **单元级**：取 21 个「有数据键但 columnDefs 为空」名单之一，调 `deriveColumnsFromRecords(rows)` → 返回 `GuestFieldDef[]` 含真实键（如 `husband_name`），`label` 为该键（无 `getGuestFieldDef` 命中时回落 key）。
2. **接口级（`getHealth`）**：对这类名单，`health` 返回的 `missing` 不再全量包含模板变量；`unusedFields` / 可选列能列出真实键。
3. **回归**：对 `columnDefs` 正常的名单，`health` 输出与修复前逐字段一致（`listKeys` 内容不变）。
4. **阻塞解除**：修复后 49 个名单中 21 个的 `listKeys` 由空变非空 → 模板变量不再被误判「缺失」。

### 具体改法描述（只描述不修改）

- **key 生成**：新增纯函数（放 core，供 editor 与 server 共用）`deriveSlug(name: string): string`，输出稳定 ASCII slug（如 `新人姓名` → `xinrenxingming` 或带 `v_` 前缀的 `/^v_[0-9a-z]{6}$/` 形态）。要求：同输入同输出、同模板内同名合并（key 相同）、不同元素不同输出。**key 绝不取中文**（规避 `TOKEN_RE` 硬伤 1、2、3：`getGuestFieldDef("新人姓名")` 为空导致元素置空、`isStandard=!key.startsWith('ext_')` 误判）。
- **编辑器写入**：勾选「设为变量」→ 写 `binding.key=deriveSlug(name)`、`binding.name=name`（人类可读）、`binding.sample=当前元素文案`（防设计态空白）。别名（name）变更**只同步 `binding.name`，绝不改 `binding.key`**（保证映射不断）。
- **命名与绑定解耦**：`binding.name` 仅用于展示与默认候选；实际取值仍走 `binding.key` → `mapping[key]` → 名单字段。
- **TOKEN_RE 不变**：模板文本仍以 `{{ascii_slug}}` 形式占位（若需要整段替换，用「整段变量元素」机制，非 token 内嵌中文）。

### 依赖任务
S1（server 读取 `binding` 前需列定义正确；editor 仅写 schema，可几乎并行，但联调需 S1）。

### 验收断言（机器可验证）

1. 文本元素填别名「新人姓名」→ 勾选 → `draftSchema` 中该元素 `binding = { key: <ASCII slug>, name: '新人姓名', sample: <当前文案>, generated: true }`，且**不含 `alias`**。
2. 改别名为「宾客姓名」→ `binding.key` **不变**、`binding.name` 更新。
3. 封面与正文都填「新人姓名」→ 两者 `binding.key` **相同**（同名合并），`collectBindings` 该变量 `elementIds` 含 2 个。
4. 别名清空 → 复选框 disabled。
5. `collectBindings(base)` 输出项含 `name` 字段且等于 `binding.name`（非 key）。
6. 非所有者打开面板 → 「设为变量」勾选区 disabled + 提示「仅模板作者可保存」。
7. **TOKEN_RE 回归**：`personalizeSchema` 对 `{{xinrenxingming}}` 正常替换；对 `{{新人姓名}}`（若残留）仍按原行为（原样保留，不报错）——但本方案不生成中文 token，故不触发。

  - **M-5** overlay 尺寸与 `scale` 同源。
- **N-1~N-5（PM + 架构补充，全部 MVP 内）**：① 多页翻页不丢已选（侧栏常驻）；② 撤销三出口（再点取消 / 列表× / 清空全部）；③ 命中率=M-4；④ 位置提示降级辅助（`describeElementPosition`，若有）；⑤ **键盘 Tab 遍历 + Enter 选中 + Esc 取消**（维文 RTL + 触屏主路径可用性底线）。
