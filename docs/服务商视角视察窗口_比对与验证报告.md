## 二、本轮修复的根因（差异的唯一来源）

**现象**：此前「业务消息」一项 ADMIN 看到 15 条、SP 仅 8 条；「我的工作台」等列表在 ADMIN 端偶发为空。

**根因 1 — 服务端 guard 改写不完整**：
`inspect-subject.guard.ts` 原先只把 `req.user.id` 改写成被视察 SP，但 `messageService.inbox` 在 `role === 'ADMIN'` 时直接返回**全部已发布消息**（绕过收件人过滤）。仅改 `id` 不生效。
修复：guard 同时改写 `id` + `role` + `regionPath`（三字段均取自被视察 SP，`regionPath` 已加进 prisma select），让 inbox 的 ADMIN 短路失效、落到收件人作用域。

**根因 2 — guard 顺序**：类级 `AuthGuard('jwt')` 会重解 JWT 覆盖 `req.user`，故 `InspectSubjectGuard` 必须与方法级 app guard 并列、置于方法级。已在 `MessageController.inbox` 加方法级 `InspectSubjectGuard`；`/api/messages/audit` 是 console 功能，故意不加 guard。

**根因 3 — 前端 `withSubject` 漏路径**：`sp/messages` 走独立 `MessageController`，原 `withSubject` 只匹配 `provider|wallet` 根，未覆盖 `messages` 收件箱（且需排除 `messages/audit`）。已补 `path === 'messages'`。

**根因 4 — 比对脚本的 SPA 状态丢失坑**：侧栏菜单是 `<div data-menu onClick=navigate>` 的 SPA 跳转而非 `<a href>`；脚本若用 `page.goto` 重载会清空 React `objectScope`（subject 未存 localStorage）→ ADMIN 看不到 subject 数据。改为 `[data-menu="..."]` SPA 跳转保留 objectScope。
