> 版本：草案 v1（基于 2026-09-18 与用户的架构讨论共识整理）
> 状态：Phase 1 已于 2026-09-18 实施（2.1 作品/模板分离 + 2.3 用户视角只读化/登录隔离 + 2.5 服务商登录重定向）；Phase 2（2.4 web 端补全用户中心）已于 2026-09-18 实施（终端用户 9 大模块搬回 web 端；运营端 user/* 维持只读观测）
> 范围：运营端与 web 端在「作品/模板」「编辑体验」「用户工作台」「RBAC 权限」四方面的职责归位

## 0. 已核实的现状基线（请逐条核对是否有误）

1. **数据模型**：`Project`（作品，`userId` 归属，状态 `draft|published`，含 `publishCode` / `templateId`）与 `Template`（模板，`authorId` 归属，状态 `PENDING/APPROVED/REJECTED/TAKEN_DOWN`，含 `category` / `price`）是**两张独立表**（`apps/server/prisma/schema.prisma`）。
2. **运营端是四视角合一控制台**（`apps/admin/src/config/resources.tsx` 的 `LAYER_HOME`）：`总台 / 代理商 / 服务商 / 用户视角`。
3. **运营端「模板管理」（`/sp/templates`，`apps/admin/src/pages/providerPages.tsx` 的 `TemplatesList`）目前是合并列表**：通过 `provider/catalog` 把服务商的 `Project`（`kind=work`）与 `Template`（`kind=template`）混在同一网格，带「来源」胶囊筛选。
4. **服务端 `catalog` 已支持 `?kind=work|template` 服务端过滤**；作品详情/草稿/发布/提升接口已存在（`apps/server/src/console/provider-console.controller.ts`）。
5. **作品相关独立页已写好并路由**：`/sp/works/:id`（详情）、`/sp/works/:id/editor`（编辑）、`/sp/works/:id/upgrade`（提升为模板，见 `apps/admin/src/App.tsx` 与 `apps/admin/src/pages/providerDetailPages.tsx`）——只是**没挂进侧边栏**。
6. **编辑器内核 `@h5design/editor` 已被 web 与运营端共用**（`EditorApp` + 各自 `editorServices` 适配层）；web 编辑器路由 `/editor/:projectId`，运营端 `/sp/templates/:id/editor`、`/sp/works/:id/editor`。
7. **web 模板库（`apps/web/src/pages/TemplateList.tsx`）服务端写死 `status:'APPROVED'`**——只展示审核通过的模板（服务商 + 官方），已符合「只有服务商/官方模板在 web 端」。
8. **运营端「用户视角」（`user/*` 层，`apps/admin/src/pages/userPages.tsx`）是完整功能性用户工作台**：我的工作台 / 我的服务商 / 我的订单 / 我的作品 / 我的评价 / 我的反馈 / 通知公告 / 业务消息 / 我的钱包 / 优惠与权益 / 账户详情。
9. **web 端用户区仅有 `/dashboard = ProjectList`（我的作品）**——**没有**订单 / 钱包 / 优惠券 / 评价 / 反馈 / 我的服务商 / 消息等 UI（`apps/web/src/App.tsx`）。
10. **总台已具备 `admin/users`（list/show/edit）**（`apps/admin/src/config/resources.tsx`）——超级管理员本就对用户数据**可读可写**，与「用户视角只读」是不同入口。

## 1. 总体原则：RBAC 主线 + 三端职责

**角色决定三件事**：看到哪个界面 · 能写什么 · 登录后去哪。

| 端 | 角色 | 职责 | 对用户数据的写权 |
|---|---|---|---|
| **web 端 (:5173)** | 终端用户 | 发现（模板库）+ 消费（已发布 H5）+ **终端用户自己的工作台** | 仅本人数据可写 |
| **运营端 (:5174)** | 服务商 / 代理商 | 作品管理 + 模板管理 + 业务（订单 / 合同 / 钱包 / 团队 …）+ **用户视角只读观测** | 他人用户数据**只读** |
| **运营端 (:5174)** | 超级管理员（总台） | 全局管理 + **用户管理 `admin/users` 读写**（裁决 / 校正 / 封禁 / 重置） | 用户数据**可读可写** |

> 注：web 端 ≠ 运营端用户视角。终端用户**不进运营端**；运营端的「用户视角」只是服务商/代理商的支持观测镜头，总台的裁决权走独立的 `admin/users`。

## 2. 五项待办（目标 / 当前态 / 改动 / 风险）

### 2.1 运营端「作品管理」与「模板管理」分离
- **目标**：`/sp/works`（作品管理，仅 `kind=work`）与 `/sp/templates`（模板管理，仅 `kind=template`）各自独立；在「服务于内容」分组内、`/sp/templates` **上方**新增「作品管理」。
- **当前态**：合并在 `TemplatesList`，带来源胶囊。
- **改动**：
  - 新增 `WorksList` 页（数据源 `provider/catalog?kind=work`，复用现有 `TemplateCard` / 网格）；
  - `apps/admin/src/config/resources.tsx` 注册 `/sp/works`（置于「服务于内容」组、`/sp/templates` 之上）；
  - `TemplatesList` 改为仅取 `kind=template`（去掉「作品」胶囊与作品分支）；
  - 补 i18n（web + admin，zh-CN / en + 其余 4 种语言）；
  - 审计 `backTo` / `navigate('/sp/templates')` 让作品相关页返回 `/sp/works`。
- **风险**：低（数据 / 接口 / 独立页均已具备）。

### 2.2 编辑体验统一（共享编辑器 + 各自工作台）
- **目标**：web 端「立即制作 / 继续编辑」与运营端编辑都打开**同一 `EditorApp`**，退出各自回对应工作台；web 端只做发现 + 消费 + 终端用户工作台。
- **当前态**：内核已共用，但 web 与运营端各有一个宿主包装（`apps/web/src/editorServices.ts` 与 `apps/admin/src/editorServices.ts`）。
- **改动**：主要是**入口与返回闭环**对齐（无需重写画布）；web 模板库「立即制作」→ `/editor/:projectId` → 返回 web 工作台；运营端 → `/sp/.../editor` → 返回运营端工作台。
- **风险**：低。

### 2.3 运营端「用户视角」只读化 + 终端用户登录隔离（低风险，建议先做）
- **目标**：`user/*` 层改为**只读观测**（去掉创建 / 编辑 / 删除动作）；终端用户不再以功能性身份登录运营端，改走 web 端。
- **当前态**：`user/*` 是功能性工作台，且用户当前可登录运营端。
- **改动**：
  - `user/*` 页面去写操作（仅展示用户作品 / 订单 / 数据）；
  - 认证层对 `USER` 角色做隔离（运营端登录拒绝或重定向到 web 端）；
  - `user/*` 仅对服务商 / 代理商 / 总台开放作支持镜头。
- **风险**：低；总台裁决权不受影响（走 `admin/users`）。

### 2.4 web 端补全用户中心（搬运用户模块，建设量大）
- **目标**：web 端成为终端用户**唯一功能性家**；把 `user/*` 层的 **我的订单 / 我的钱包 / 优惠与权益 / 我的评价 / 我的反馈 / 我的服务商 / 业务消息 / 通知公告 / 账户详情** 移植到 web 端。
- **当前态**：web 端仅有「我的作品」。
- **改动**：在 web 端新建 / 移植上述约 8–9 个用户模块（UI + 复用现有 API）；完成后运营端 `user/*` 层可彻底只读。
- **风险**：中（实质建设，非复制粘贴）。

### 2.5 服务商登录落点（角色重定向）
- **目标**：服务商创作 / 管理 / 发布**全在运营端**（本就在 `/sp/works`、`/sp/templates`）；web 端不承载服务商操作。
- **登录形态**：
  - 最佳＝服务商走**独立运营端登录 (:5174)**；
  - 若用 web 端统一登录，则**认证后按角色直接重定向到运营端工作台**（而非先落消费者首页再点菜单）；
  - 账号菜单「我的工作台（服务商）」保留为跨端便利入口，**不作唯一路径**。
- **风险**：低。

## 3. 分阶段实施路线

- **Phase 1（低风险，先落地，立刻消除混乱）**：2.1 作品/模板分离 + 2.3 用户视角只读化 + 用户登录隔离 + 2.5 角色重定向。**已完成（2026-09-18）**。
- **Phase 2（建设）**：2.4 web 端补全用户中心（9 大模块搬回 web 端，后端 `/api/user/*` 零改动复用）。**已完成（2026-09-18）**；运营端 `user/*` 维持只读观测。
- **贯穿**：2.2 编辑闭环对齐（可与 Phase 1 同步做）。

## 4. 待确认的关键决策点（重点防偏差）

1. **命名**：web 端「我的作品」升级叫 **「我的工作台」**；运营端新菜单叫 **「作品管理」**（与「模板管理」对称）——认可。
2. **新建入口**：作品管理放「＋新建作品」、模板管理放「＋新建模板」，各管各的空白稿。如果需要把作品升级为模板，则提交为模板的流程转到“服务管理”管线上。服务管理里仔细观察和设置模板相应属性后，再升级进入到审核流程上。
3. **登录形态**：服务商要走「web 统一登录 + 角色重定向」——认可
4. **Phase 1 范围**：同意先只做 2.1 + 2.3 + 2.5（不动 web 端用户中心）
5. **「用户视角」只读的例外**：是，确认总台仍走 `admin/users` 读写、不碰 `user/*` 层

---

## 5. 明确不在本次范围

- 终端用户从模板「制作」出的作品仍 `userId=本人`，只在其 web 工作台——边界不变。
- 模板审核流（`PENDING→APPROVED/REJECTED/TAKEN_DOWN`）、付费 / 分账等既有业务逻辑不动。
- 代理商层（agent）本次只做「对用户数据只读」，不扩展其能力。
