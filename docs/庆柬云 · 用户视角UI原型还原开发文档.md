> 用途：指导运营端（apps/admin，React + Refine + Ant Design 5）按本原型还原「用户视角」全部页面与交互。
> 依据：
>
> `UI_Design/index.html`
>
> （分片源 p1~p9.html，
>
> `_rebuild3.py`
>
>  拼接，最新 209,968+ chars）中 VIEW=user 的全部菜单、页面、对话框实现。
> 定位：一个后端・分层治理・总台统筹。用户视角是四层角色中的最底层，数据作用域为自身（SELF），只读个人资料 + 可发反馈 / 评价 / 入驻申请。

## 二、用户视角定位与能力



| 维度   | 说明                                                               |
| ---- | ---------------------------------------------------------------- |
| 角色   | 注册客户（USER），数据作用域自身（SELF）                                         |
| 入口   | 顶部视角切换「用户视角」；总台管理员可切至用户视角代查（默认只读 RO，超级管理员可写）                     |
| 只读守卫 | 所有写操作（评价提交、反馈提交、账户编辑、入驻申请）在 `RO=true`（运维管理员只读）时禁用并提示             |
| 顶部独有 | 「成为代理商」「成为服务商」升格入口按钮（用户视角两个，服务商视角一个）                             |
| 账户胶囊 | 头像首字 + 昵称 + 等级，下拉含快捷入口（我的订单 / 待付款 / 进行中 / 我的服务商）、待办事项、账号管理（账户详情） |

## 四、顶部导航与全局组件

### 4.1 顶部栏结构（自左至右）



1. 品牌区：Logo「庆柬云」+「管理后台」

2. 侧栏折叠 + 视角切换器（总台视角 / 代理商视角 / 服务商视角 / 用户视角四个按钮，当前高亮）

3. 面包屑：`当前层级 crumb / 当前页面 page`

4. `#topActs` 升格入口区（仅用户视角渲染「成为代理商」「成为服务商」，服务商视角渲染「成为代理商」）

* 提交后按钮置灰，文案变「已提交・审核中」（状态常量 `UP_SUBMITTED`）

1. 账户胶囊（阿里云风格下拉）：头像首字、昵称、等级标签；下拉含快捷入口、待办事项、账号管理、退出登录

### 4.2 对象视角工具栏（总台切至用户视角时显示）

`#objPick`：左侧「搜索」标签 + 组合框（输入框 placeholder「搜索 ID / 用户名 / 昵称 / 手机号…」+ 下拉 `#objList`）+「搜索」按钮 + 对象标签 `#objTag` + 右对齐「返回总台」按钮（`alignExit` 与页头角色标签右缘对齐，`marginRight` 动态计算）。

搜索交互：



* 点击「搜索」：按 `ID/用户名/昵称/手机号/区域` 模糊匹配当前对象池（用户视角 = USERS）；

* 唯一命中 → 直接切换对象视角（`setCurObj`），列表 / 看板数据全部关联该对象；

* 多条命中 → 展开下拉列表，点选后关联；

* 空关键词点击 → 提示输入。

* 输入框 focus 展开下拉、input 实时过滤；点击对象下拉项 → `setCurObj`。

### 4.3 通用列表页骨架（pg-list）



```
pghead（标题/副标题 + sp + 角色chip）

toolbar：筛选按钮组(#listFilters) + 搜索框(含 ✕ 清除按钮) + 搜索按钮 + 导出 + 新建按钮(#listNew)

panel：表头(#listTable thead) + 表体 + 分页条（共 N 条 · 上一页/下一页占位）
```



* 筛选：`f` 数组渲染 `.chip`，含计数 / 全部；点击按 `fcol` 分类过滤，当前选中高亮。

* 搜索：关键词匹配行内文本；`✕` 一键清空输入。

* 新建：`new:1` 时显示「＋ 新建」按钮；普通页 `openModal(key,0,'new')`（空表单 + 编号自动续号追加到列表末尾）；反馈页 `openFbNew` 跳新增反馈页。

* 行操作：按 `acts` 类型渲染（详见 § 六各页）。

### 4.4 状态标签规范



| 标记      | 语义       | 用例                 |
| ------- | -------- | ------------------ |
| `#ok`   | 成功 / 已处理 | 已完成、已发布、已到账、已读、已通过 |
| `#warn` | 待处理 / 警告 | 待服务、待支付、待评价、未读、处理中 |
| `#bad`  | 失败 / 停用  | 已取消、已驳回、停用         |
| `#ac`   | 进行中 / 强调 | 履约中、待确认收货          |
| 无标记     | 中性       | 普通文本               |

* 用户资料卡 `#uCard`：


  * 首行：首字头像 + 姓名 + 等级标签（按 TIERS 色）；

  * 元信息：`ID U001 · 手机 137****5521 · 乌鲁木齐 · 注册 2025-11-02`；

### 5.5 我的反馈（u-complaints）



| 项   | 内容                                                                                                          |
| --- | ----------------------------------------------------------------------------------------------------------- |
| 表头  | 编号、主题、类型、对象、时间、状态                                                                                           |
| 数据  | 新增反馈记录（`FB_NEW_ROWS`，编号 `FB-2713` 起由 `FB_SEQ` 自增）+ 样例：FB-2708 售后处理中 (待回复)、FB-2704 建议 (已回复)、FB-2698 咨询 (已回复) |
| 筛选  | 全部 / 待回复 / 已回复                                                                                              |
| 行操作 | 查看（跳反馈详情页 `pg-fbdetail`）；新建（`＋ 新增反馈` → `pg-fbnew`）                                                          |

**新增反馈页（pg-fbnew）**：



* 必填：反馈主题、反馈类型（售后 / 建议 / 咨询 / 投诉 / 其他）、**反馈部门**（服务商负责人 / 代理商 / 平台 (直接上报)，提示处理层次自下而上）、反馈对象（平台 / 具体服务商）、反馈内容。

* 附件上传（选填，JPG/PNG ≤5MB）。

* 按钮：保存草稿（写入 `FB_NEW_ROWS` 并跳回列表）/ 提交反馈（`FB_SEQ` 递增生成新编号，进入处理流程）。

* 再次进入新建页时重置表单，不复用上次记录。

**反馈详情页（pg-fbdetail）**：



* 左列基本信息（编号 / 主题 / 类型 / 对象 / 提交时间 / 当前状态 / 处理部门）；

* 右列处理流程（`fbTrace` 按部门渲染步骤链：提交反馈→服务商负责人受理→代理商介入→平台升级；服务商 / 代理 / 平台视角步骤不同）；

* 「意见与回复」表格：回复内容 / 处理时间 / 操作人，**最新在上的纵向日志**，回复内容自动换行，区域垂直滚动条；

* 底部发送消息区：用户可继续补充消息，提交后插入表格顶部「我・刚刚」记录并追加至 `FB_THREAD`。

* 处理链与升级：用户→服务商负责人→代理商→平台逐层贯穿；服务商 / 代理商 / 总台视角详情页按各自层级展示对应「升级」操作。

## 六、对话框规范

### 6.1 通用弹窗骨架（#modal）



* 头部：`rolechip` 类型标签（订单 / 服务商 / 券 / 流水 / 评价 / 消息 / 反馈）+ 标题 + ✕。

* 主体：`#mKv` 键值详情（左标签右值）；可编辑时切换 `#mForm` 表单（必填项红色 `*`，`select`/`date`/`textarea` 等组件）。

* 底部按钮区：`#mEdit`（编辑 / 保存）、`#mCancel`（关闭 / 取消）、`#mReject`（驳回）、`#mApprove`（通过）—— 用户视角只读页仅「关闭」。

### 6.2 评价 / 追评弹窗（openEvalModal）



* 入口：我的订单 / 我的服务商行内「评价」；已评价后按钮变「追评」。

* 内容：对象行（订单服务 / 服务商）+ 综合评分（5 颗星点击，颜色 `#f5a623` 实心、`#d8d8d8` 空心，右侧满意度文案：很不满意 / 不满意 / 一般 / 满意 / 非常满意）+ 评语必填 textarea。

* 追评：预填上次星级与评语。

* 提交：校验评语非空 → 写回行数据（订单：状态置 `#ok 已评价`、存星级与内容；服务商：更新评分列）→ 关闭刷新 → alert 提示「评价将在平台审核后公开展示」。

### 6.3 入驻申请弹窗（upModal）



* 成为服务商：申请角色 = 服务商、审核流程「辖区初审 → 总台终审」、开通权限；显示**服务类型复选框**（服务字典 11 项，`#upScopes`）+ **开展服务区域三级联动**（省 / 市 / 区县，`#upProv/#upCity/#upDist`）+ 申请理由必填。

* 成为代理商：审核流程「总台初审 → 总台终审」；显示**计划代理区域三级联动**（省 / 市 / 区县，层级联动）+ 申请理由必填。

* 提交：校验理由与区域（服务商另需勾选至少一个服务类型）→ `UP_SUBMITTED` 置位 → 按钮变「已提交・审核中」。

* RO 只读时打开弹窗被拦截提示。

### 6.4 调整用户数据弹窗（#uAdjModal）

工作台「调整用户数据」→ 打开弹窗（展示当前用户姓名 / ID / 城市 / 等级）→ 调整会员等级、余额、积分（用于等级测试与功能验证），保存后刷新工作台 KPI 与标签。
