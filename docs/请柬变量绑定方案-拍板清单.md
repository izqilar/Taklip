## 二、架构 Q1–Q9（主编号）

| # | 议题 | 决策 / 建议 | 影响 |
|---|---|---|---|
| **Q1** | 「组件别名」在文本元素上的真身是 `el.name` 还是 `el.alias`？ | ✅ **已澄清（事实，非决策）**：是 `el.name` | 根源是 `editor.json:159` 与 `:233` **两个字段共用"组件别名"同一中文标签**。`alias` 在 **9 种非文本组件**上，文本元素根本没有该字段。按 `el.name` 设计（请柬个性化 99% 是文本） |
| **Q2** | **admin 两端（用户视角 / 服务商视角）是否同期做映射弹窗？** | ✅ **已定：三端同期**（web 重写 + admin ×2 从零新增） | 前端工作量 +30%；三端**必须复用同一组件** `packages/invitation-mapping`。只做 web 则"服务商做模板 → 客户生成"这条核心分发路径仍跑不通 |
| **Q3** | 放开 LOCKED 后改映射，是否需要**运营审计**（谁/何时/改前改后）？ | 🔵 **建议：不需要加审计表** | 改映射不改变人员集合、不绕过配额，**无套利路径**；首渲留痕已有 `RenderSnapshot`，足够追溯。加表是 MVP 不该付的成本 |
| **Q4** | 免费用户改映射后重渲，是否计入「重渲次数」限制？ | 🔵 **建议：不计入，保持现状**（保留"带水印 + 仅前 3 条"两道闸） | 改映射是**纠错**不是新增产出；若纠错要钱，用户会放弃纠错直接拿废品走人。**RERENDER 不占配额是既有现状**，不应借本次改造顺手改收费口径 |
| **Q5** | 变量名唯一性作用域：整个模板唯一，还是整个页面唯一？ | 🔵 **建议：整个模板唯一** | 与"同名即合并（多处复用）"一致：封面「新人姓名」+ 正文「新人姓名」应合并，这正是多处复用的典型场景 |
| **Q6** | **方案 D 的交互形态：下拉选择 还是 画布可视化点选？** | ✅ **已定：画布可视化点选**（老板知情选择，当时标注成本 3–5×）<br>🔄 **成本重估：实际 1.5–2×**（见下方说明） | 消歧隐患从结构上解决。但**新引入 5 条交互规格必须 MVP 内一并做完**，见 §四 |
| **Q7** | 是否有「变量市场 / 预设变量包」？ | 🔵 **建议：不做"市场"**（需运营供给，是另一条业务线）；**但加一个近乎零成本的常量候选列表** `COMMON_VARIABLE_NAMES`（新郎姓名 / 新娘姓名 / 桌号 / 场次 / 日期） | 婚礼场景高度重复，这 5 个能覆盖多数情况，显著降低"生成者要自己想名字"的成本——而"想名字"正是老板要消除的负担 |
| **Q8** | **方案 D 的绑定结果是否默认「保存为模板变量」？** | ✅ **已定：默认勾选，但仅模板作者可见可勾** | 打通 D→C 闭环（否则 D 退化为一次性临时补丁）；非所有者（终端用户用服务商模板，最常见场景）**置灰 + 提示「仅模板作者可保存到模板」**，规避越权与写冲突 |
| **Q9** | **换名单 = 新项目 → 绑定要重配；继承是否进 MVP？** | ✅ **已定：接受重绑；继承 P1，不进 MVP** | 老板核心诉求"同项目内改名单 → 重生成 → 出图变"**不受影响**。P1 再按 `projectWhere(scope)+templateId` 继承（键必须含完整 scope 四元组，防跨客户泄露）+ 标明"沿用来的" + 提供"清空重新选择" |

## 三、产品独有议题（A1–A5）

| # | 议题 | 建议 | 影响 |
|---|---|---|---|
| **A1** | **未映射变量：阻断还是留空隐藏？** | 🔵 **三级判定**：① `变量数>0 且 已映射=0` → 🔴 红条阻断（保留「跳过，生成统一版式」显式出口）② `required` 变量未映射 → 🔴 阻断 ③ 名单完全无可用列 → 🔴 阻断 ④ 部分未映射（已映射 ≥1）→ 🟡 琥珀放行，逐项列出"将留空/隐藏，共 N 张" | **"名单某行值为空"与"变量根本没映射"性质不同**：前者是数据问题（影响个别几张、用户意图明确 → 不阻断），后者是配置问题（影响全部 N 张、用户大概率没看懂 → 必须拦截）。若一律放行，产出一批完全不含名单信息的请柬而流程显示"成功"，等于重演 104/108 的静默错误 |
| **A2** | **创作期是否彻底移除「变量字段」下拉（`guest_name` / `ext_xxx`）？** | 🔵 **彻底移除** | 保留会让新机制的心智负担回潮。`VariablePanel` 保留 key 可见以便排障 |
| **A3** | **变量名是否允许重名？** | 🔵 **允许（同名即合并）** | 同名合并是"同一变量多处复用"的天然表达；配「命中 N 处」+「拆分为独立变量」防止误合并 |
| **A4** | **存量 4 个已绑定模板（`ext_husband`/`ext_wife`）如何迁移？** | 🔵 **自动补 `name`「新郎/新娘」** | 低风险，且能立刻让现有婚礼模板在 `husband_name` 名单上跑通。注：这 4 个 binding **只存在于 `draftSchema`、从未发布**，本身不保险 |
| **A5** | **LOCKED 后是否放开映射修改（现返回 409）？** | 🔵 **建议：放开** | 现状下用户首渲后发现映射错列 → 409 被拒 → 只能弃项目重开且**已耗额度不退**，等于把"改映射"变成"一次定终身的赌博"。改映射与 FR-3 锁人员集合**正交**，不绕过计费。（架构 Q3/Q4 均以"放开"为前提） |

## 四、⚠️ Q6 拍板后的成本修正与新增规格

### 4.1 成本重估：3–5× → **1.5–2×**（v7 修正）

老板是在"成本 3–5×"的标注下做的知情选择，**实际没那么贵**。原估建立在错误假设上（默认画布渲染要引入 Konva / `@h5design/editor`）：

| 事实 | 代码依据 |
|---|---|
| 服务端出图用的就是 `SchemaRenderer` | `apps/web/src/pages/ExportRenderPage.tsx:15,178` |
| 每个元素 DOM 自带 `data-element-id` | `packages/render/src/SchemaRenderer.tsx:969`（:1445 已有按该属性回查元素的逻辑） |
| **Admin 两端已在用** | `UserInvitationTemplatePicker.tsx:2,330`；`spInvitationBatch.tsx:15` 注释明写"渲染内核一致" |
| 纯 React DOM，无 Konva | `SchemaRenderer.tsx:1-3` |

⇒ 只需在既有 `SchemaRenderer` 外加一层 overlay，**admin 两端无新增 bundle 成本**。

> **建议回传老板**：他批的不是"一个很贵的方案"，实际只比下拉方案贵一点。这是好消息，但不应让他继续持有错误预期。

### 4.2 新增规格（下拉方案没有，必须 MVP 内一并做完）

> **若只做"能点选"而不做这些，会出现"点错没法改、也不知道有没有选对"的半成品——这比不做点选更糟。**

| # | 新问题 | 产品规格 |
|---|---|---|
| **N-1** | **多页模板如何翻页点选** | 请柬常见 2 页（封面 + 正文）。弹窗内需**页面切换器**（上一页/下一页 + 「第 1/2 页」指示），且**翻页不丢失已选绑定**（绑定列表侧栏常驻、不随页清空）。建议翻页时**自动跳到下一个"疑似变量"所在页**，减少手动翻找 |
| **N-2** | **点选后如何撤销 / 改选** | 三条出口缺一不可：① 再次点击已选元素 → 取消选中；② 候选列表每项带「×」解绑；③ 顶部「清空全部重新选择」。**若没有撤销，用户点错一次就得关掉弹窗重来** |
| **N-3** | **弹窗内画布尺寸与命中率** | 画布需等比缩放；缩放后小字号文本可能点不中 → **热区不小于 24×24px**，重叠元素按 `zIndex` 取最上层；overlay 与画布 scale 必须同源 |
| **N-4** | **页码/位置提示（保留，降级为辅助）** | 架构侧已实现为 core 纯函数 **`describeElementPosition`**。用途：① 点中即高亮边框 + 候选列表**同步滚动定位**；② 再次打开弹窗时仍需文字标识；③ 键盘遍历时的可及信息 |
| **N-5** | **键盘可达性**（架构侧新增，产品侧强烈支持） | 仅鼠标点选对**维吾尔文 RTL + 触屏**场景不友好 → 必须支持 **Tab 遍历候选元素 + Enter 选中**。维文是核心用户群、触屏是主要设备形态，**这不是"无障碍加分项"而是主路径可用性** |

**架构侧另提的点选特有必须项 M-1~M-5，其中 M-3 产品侧重点推荐**：

| # | 必须项 | 不做会怎样 |
|---|---|---|
| M-1 | `animated={false}` | 入场/循环动画让元素在点击瞬间 `opacity:0` 或位移 → **点不到或点错位** |
| M-2 | 字体预加载 | 字体未加载完用 fallback 渲染 → 行宽/换行不同 → **高亮框与实际文字错位**（须与出图页同口径） |
| **M-3** | **预览用「首条名单记录个性化后」的 schema** | 只显示设计态样例 → 用户看到的是**假文案**，无法判断选对了没有。**它把"点选"从「挑个位置」升级为「看着真实效果挑」**——`personalizeSchema` 是 core 纯函数、零 DOM，前端可直接调，成本几乎为零 |
| M-4 | 热区 ≥24×24 + zIndex 取最上层 | 小字号点不中、重叠点错 |
| M-5 | overlay 与 scale 同源 | 高亮框错位 |

> N-1~N-5 与 M-1~M-5 **全部写进 MVP，不允许降级为"细节"。**
