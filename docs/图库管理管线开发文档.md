# 图库管理管线 开发文档

> 范围：在现有 `asset` 模块与 admin 菜单配置基础上，新增"我的图库"私有图库能力，覆盖服务商端与终端用户端，并统一图片存储为 WebP。  
> 本文档已落盘至 `docs/图库管理管线开发文档.md`，等待复核；复核通过后将按 §10 进入实施。  
> 现状锚点（已探查）：菜单定义集中在 `apps/admin/src/config/resources.tsx`；上传/列举/删除后端在 `apps/server/src/asset/*`；隔离范式在 `apps/server/src/common/interceptors/data-scope.interceptor.ts`；成品对外发布在 `apps/server/src/publish/*`。

---

## 1. 背景与目标

- 用户（服务商 / 终端用户）需上传婚纱照等像素图片，装饰本人请柬作品；图片须严格隔离、仅本人可见、仅存于本人私有图库。
- 现有 `asset` 模块已支持上传/列举/删除，但存在缺口：磁盘落点无用户前缀、`/uploads/*` 公开可读、无配额、无压缩、无缩略图、无裁剪、无预览（签名 URL）。
- 本管线目标：补齐配额控制、WebP 统一存储、预览/裁剪、菜单入口，并强化跨用户隔离。

## 2. 功能需求

### 2.1 服务商端（SERVICE_PROVIDER）

- 在"服务与内容"（`servicecontent`）分组的"作品管理"菜单**上方**新增"我的图库"菜单，路由 `/sp/gallery`。
- 详情页能力：
  - **浏览**：网格展示本人全部已上传图片（缩略图 + 文件名 + 尺寸 + 体积 + 上传时间）。
  - **上传**：点击上传，前端预校验 + 后端校验，写入本人图库。
  - **预览**：点击单图放大预览（大图，经签名 URL，限时）。
  - **删除**：单图删除，含级联保护（被作品引用时提示）。
  - **裁剪**：对单图裁剪，生成派生图（非破坏原图）。
- 配额：**上限 见习代理 10张 / 铜牌代理 16张 / 银牌代理20张 / 金牌代理26张 / 钻石代理30 张**。达到上限后上传入口禁用，并展示引导购买增值服务的入口（跳转独立"扩容套餐页"）。

### 2.2 终端用户端（USER）

- 新增"资源中心"（`resourcecenter`）分组；将"我的作品"从"交易中心"（`trade`）移至该分组。
- 在"资源中心"内新增"我的图库"菜单（路由 `/user/gallery`），菜单顺序为：**我的图库 → 我的作品**（等）。
- 终端用户图库所有交互与逻辑**与服务商端保持一致**（同一套 `GalleryPage` 组件，仅归属人取当前会话用户）。
- 配额：**免费用户 4 张 / 银卡用户 6 张 / 金卡用户10张 / 黑金用户16张**；超额同样禁用上传并引导至独立"扩容套餐页"。

### 2.3 图片存储（统一 WebP）

- 任意"像素图片"上传后，后端统一解码并**重编码为 WebP**（平台体积最小格式），以节省存储。
- 保留原图尺寸/比例；WebP 质量按"目标 ≤2MB"自适应（见 §7 边界）。
- 同时生成 `thumb(≤200px)`、`preview(≤1080px)` 两档缩略图，供网格/预览使用。
- 音频/视频不进图库，走既有 `asset` 的 audio/video 通道（保持原格式）。

### 2.4 配额与超量引导

- 配额值来源：服务商固定 30；用户由 `plan`（FREE/PAID）推导 4/20（不写死，放配置/订阅）。
- 达到上限：上传按钮禁用 + 文案"已达上限 N 张，扩容后可继续上传" + "去扩容"按钮跳转扩容套餐页。
- 配额释放：图库删除并物理清除后，计数回退（软删期间仍占额，硬清后释放）。

## 3. 数据模型（扩展现有 `Asset`）

```prisma
model Asset {
  id          String   @id @default(cuid())      // 必须 cuid/uuid，禁自增（防枚举/IDOR）
  userId      String                          // 归属人；所有查询 WHERE userId=:me
  kind        String   // 'image' | 'audio' | 'video'
  storageKey  String   // 对象键 users/{userId}/imgs/{cuid}.webp  ← 取代裸 url
  mime        String
  width       Int?
  height      Int?
  size        Int      // 存储后体积（WebP）
  compressed  Boolean  @default(true)
  sha256      String?  // 完整性/去重
  derivedFrom String?  // 裁剪派生的源 assetId
  status      String   @default("ready") // uploading|ready|deleted
  deletedAt   DateTime? // 软删
  createdAt   DateTime @default(now())
  refs        WorkImageRef[]
}
model WorkImageRef {   // 图↔作品 引用（编辑器选用时写入）
  id String @id @default(cuid())
  workId String; assetId String; usage String
  crop Json   // {x,y,w,h,rotation,scale,zoom}
}
```

- 配额计数 = `COUNT(Asset WHERE userId=:me AND kind='image' AND deletedAt IS NULL AND status='ready')`。
- 新增 `MenuGroupKey.resourcecenter` 及分组标题 i18n `group.resourcecenter = '资源中心'`。

## 4. 系统架构与后端改造（基于现有 asset 模块）

- **存储层**：将 `asset.controller` 的 `diskStorage` 改为对象存储 SDK（OSS/S3/COS/MinIO），落点 `users/{userId}/imgs/{cuid}.webp`；DB 写 `storageKey`，不再存公开 `url`。
- **上传校验**：魔数判定真实类型，白名单 `jpg/png/webp/gif/avif/bmp/tiff`（**SVG 拒绝**，防脚本）；维度上限（最长边 ≤8000px）。
- **WebP 转换**：用 `sharp` 解码→重编码 WebP；迭代降质/降维至 ≤2MB（见 §7）。
- **配额原子校验**：上传在事务内 `count+1 <= limit` 才落库，防并发超额；否则 `429`。
- **预览（签名 URL）**：新增 `GET /api/assets/:id/url` → 后端鉴权后签发 **TTL 5~15min** presigned URL；废弃公开 `/uploads/*`；CORS 仅放行本域。
- **裁剪**：新增 `POST /api/assets/:id/crop`（rect + rotation/scale）→ 后端 sharp 烘焙 → 生成 `derivedFrom` 新 Asset（非破坏原图）。
- **删除**：软删 `deletedAt`；后台任务过保留期后物理删对象+行+清 CDN；删除前查 `WorkImageRef` 级联保护。
- **隔离**：所有查询 `WHERE id=:id AND userId=:me`；查不到统一 `404`（不泄归属）；复用 `data-scope.interceptor` 范式。

## 6. 交互流程

### 6.1 上传

浏览器选文件 → 前端校验（类型/大小） → `POST /api/assets/upload`（JWT） → 后端配额原子校验 → 魔数+维度校验 → sharp 转 WebP（≤2MB）+ 生成缩略图 → 写对象存储 `users/{uid}/imgs/{cuid}.webp` → 写 Asset 行（status=ready）→ 配额 +1 → 返回 metadata。超额返回 `429` 并前端展示扩容引导。

### 6.2 浏览/预览

进入图库页 → `GET /api/assets?kind=image` 返回本人图片（缩略图用 preview 档） → 点击单图 → `GET /api/assets/:id/url` 取签名 URL → 弹窗大图预览。

### 6.3 删除

点击删除 → 查 `WorkImageRef`：被引用则弹窗提示"该图用于 N 个作品，删除后作品将缺失此图"并阻止/二次确认；无引用则软删 → 后台硬清释放配额。

### 6.4 裁剪

点击裁剪 → 打开裁剪 UI（框选 x,y,w,h,rotation,scale） → `POST /api/assets/:id/crop` → 后端 sharp 烘焙 → 生成 `derivedFrom` 新 Asset（原图保留） → 网格新增该派生图。

### 6.5 选用到作品（与编辑器衔接）

图库"选用"动作 → 写入目标作品的 `WorkImageRef(assetId, crop)` → 编辑器（`@h5design/editor`）按 `assetId` 经签名 URL 取图渲染；原图不破坏，crop 仅作变换参数。

## 7. 边界条件

- **格式**：仅像素图片（jpg/png/webp/gif/avif/bmp/tiff）；**SVG 拒绝**（可含脚本）；音频/视频不进图库。
- **单文件上传上限**：沿用 30MB，超过即拒。
- **存储体积目标**：WebP ≤ 2MB。实现：先降质（q≈82）→ 仍超则按比例缩最长边（如 4000→降）→ 再压，循环至 ≤2MB；极端图封顶（如 ≤5MB）并记日志告警，仍保证可存。
- **维度上限**：最长边 ≤ 8000px，防解压炸弹 DoS。
- **配额并发**：事务/行锁防两人同时传冲超上限。
- **配额降级**：付费→免费时，已有 20 张不自动删，禁止新上传并提示"请删至 ≤4 张"；不破坏已有作品。
- **隔离语义**：跨用户不可见/不可混用；查不到统一 `404`（不泄露"是否存在/归属谁"）；签名 URL TTL 短且绑定请求上下文。
- **软删窗口**：删除后保留期（如 30 天）内仍占额，硬清后释放。
- **多语言**：菜单/文案按既有 i18n 规则（缺 key 用 defaultValue），不阻断渲染。
- **失败重试**：上传失败可重试；大图建议前端显示进度。

## 8. 用户级隔离与防跨用户泄露（重点）

1. **行级归属**：每个接口 `WHERE id=:id AND userId=:me`；查不到 `404`（非 `403`）。
2. **存储键前缀含 userId**：`users/{userId}/imgs/{cuid}.webp`；即便签名 URL 泄露，键仍被命名空间包裹。
3. **私有桶 + 短时签名 URL**：读图一律后端鉴权后签发 TTL 5~15min presigned；CORS 仅本域，禁匿名 GET。
4. **ID 不可枚举**：Asset.id 用 cuid/uuid，禁自增主键（防 IDOR 遍历）。
5. **引用闭环**：作品只存 `assetId`；渲染时后端先校验 `asset.userId === work.userId` 才解析 URL——结构上杜绝跨用户引用。
6. **成品对外 ≠ 图库暴露**：宾客看到的请柬是发布态成品（bake/绑定 publishId 的签名 URL），绝不分发私人图库目录。
7. **删除级联保护**：被作品引用时拦截/提示，避免误删致串档缺图。
8. **审计**：复用 `audit` 模块记录"谁/何时/读哪张图"，便于溯源。
9. **软删 + 定时硬清**：`deletedAt` 标记 → 后台物理删对象+行+清 CDN 缓存。
10. **限流**：复用 `rate-limit.guard` 对上传接口按用户限流。

## 9. 验收标准

- [ ] 服务商端"服务与内容"分组中，"我的图库"位于"作品管理"上方，可上传/预览/删除/裁剪。
- [ ] 终端用户端出现"资源中心"分组，含"我的图库、我的作品"（顺序正确），"我的作品"不再出现在"交易中心"。
- [ ] 服务商图库达 30 张时上传禁用并引导扩容；用户免费 4 / 付费 20，超额同样引导。
- [ ] 上传任意像素图片后存储为 WebP，且 ≤2MB（极端图封顶并告警）。
- [ ] 跨用户 A 无法列举/预览/删除 B 的图（接口 404；签名 URL 越权拒）。
- [ ] 删除被作品引用的图时给出级联提示。
- [ ] 0 console / 接口报错；i18n 缺 key 不崩溃。
