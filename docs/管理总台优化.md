# 管理总台（ADMIN）优化改造方案 — 菜单重构 + 核心治理模块补全

> 目标：以「用户 / 服务商 / 代理商」三个已定型的视角为基准，补全管理总台缺失的业务治理闭环，
> 重新规划其菜单结构与页面 UI，使四个视角的业务逻辑闭环、交互与视觉风格完全一致。
> 范围：**核心治理模块优先**（平台合同管理、服务与作品审核、招商与意向池、结算总览与分账费率）+ 菜单重构。
> 数据策略：**前端先以「该功能即将上线」占位**（遵循项目强制规范，禁止伪造实现），后续按本方案 Phase 1–4 接真实端点。

---

## 1. 现状基线

### 1.1 管理总台已有（~19 个真实页面，resources.tsx `layer:'console'`）

经营总览、代理商管理、服务商管理、用户管理、模板审核、订单管理、入驻审批、钱包总览、
提现审核、消息中心、评价与反馈中心、区域管理、角色与权限、账户详情、系统设置、字体管理、
操作日志、红线词库。路由与组件映射见 `apps/admin/src/App.tsx`（约 40 个 lazy 路由）。

### 1.2 缺口（对比另外三视角，总台作为「全盘治理」视角应 oversight 却缺失的模块）

| 缺失模块 | 服务商/代理商已有对应 | 总台现状 |
| --- | --- | --- |
| 平台合同管理 | sp/contract、agent/contract | ❌ 无 |
| 服务审核 | agent/service-review | ❌ 无（仅有模板审核） |
| 作品/内容审核 | agent（projects/pending 审核） | ❌ 无 |
| 招商申请 + 意向池 | agent/invest、agent/pool | ❌ 无 |
| 结算总览 | agent/settle（复用辖区钱包） | ⚠️ 仅有钱包总览/提现审核 |
| 分账费率配置 | — | ❌ 无 |

### 1.3 后端可复用性（关键发现，决定占位后可低风险接后端）

后端 `apps/server/src` 已存在全部领域端点，总台可经 `DataScopeInterceptor`（ADMIN=ALL，去 regionPath 过滤）直接复用：

- 合同：`provider-console/contracts`、`agent-console/contracts`（GET/PATCH/advance/sign）
- 服务/作品审核：`agent-console/projects`(pending + review)、`agent-console/templates`(review)
- 招商/意向：`agent-console/recruits`（GET/POST/PATCH/convert）
- 结算：`agent-console/wallet`、结算统计 `admin/stats`
- 红线：`console-dashboard/redline-words`（已接 `admin/redline-words`）

## 2. 设计原则（四视角一致性铁律）

1. **复用既有共享组件**，不另造轮子：
`PageHead`(title/sub/chip)、`GRID.kpis|duo|trio`、`Panel`(title/hint)、`KpiCard`(main 主卡)、
`DealOrdersPanel`、`ChartCard`+`HorizontalBarList`/`TrendArea`、`TodoList`、`DataTable`(dense)、
`GenericListPage`、`ReviewModal`、`Pill`/`StatusTag`、`FilterBar`、`AgentComingSoon`/`PlaceholderPage`。
2. **视觉令牌统一**（来自 `apps/admin/src/config/theme.ts`）：
主题色朱砂 `T.accent`(#c24b2e)；面板底 `T.panel2/3`；字号令牌 KPI 27 / 页头 18 / 面板头 14.5 / 表头 12.5 / 菜单 13.5；
金额 `formatCents`（分→元）；手机号 `maskPhone`。
3. **菜单交互一致**：分组标题栏（暖石底 + 朱砂左竖条 + 13.5px 粗体 + 折叠箭头 + 折叠态汇总待办数），
选中项（朱砂软底 + 3px 左竖条 + 朱砂字）—— 逻辑全部已在 `LayerSider.tsx` 实现，新分组自动套用，无需改样式。
4. **角标真实化**：菜单角标 = `GET /api/console/badges` 下发的真实待处理子集，绝不统计全表、绝不硬编码数字。
新增模块的 badge 键在接后端 Phase 再补（见 §6）。
5. **占位规范**：未实现模块一律 `AgentComingSoon`/占位页显示「该功能即将上线」，不伪造数据、不伪造交互。
6. **视察视角门控**：总台属 ADMIN，`?subject=` 视察机制仅属 ADMIN（见工作记忆），
新页面须遵循 `layerContext.isOwnView` 放行，绝不强制选 subject。

## 3. 重新规划的管理总台菜单结构（定稿）

分组顺序以 `GROUP_ORDER` 全局控制；新增 `contract` 分组键，复用 `contentreview`(内容审核)、`recruit`(招商拓展) 标签。

```
管理总台 (admin/console)                                    [ADMIN · 全盘治理]
├─ 总览与治理 (overview)
│   ├─ 经营总览          admin/dashboard
│   ├─ 代理商管理        admin/agents
│   └─ 服务商管理        admin/provider-review        (badge: providerReview)
├─ 内容审核 (contentreview)        ← 原「模板审核」从 ops 移入，补齐服务/作品审核
│   ├─ 作品审核          admin/work-review            (新·占位)
│   ├─ 模板审核          admin/templates              (badge: templates)
│   └─ 服务审核          admin/service-review         (新·占位)
├─ 运营监管 (ops)
│   ├─ 订单管理          admin/orders
│   ├─ 用户管理          admin/users
│   └─ 入驻审批          admin/qualifications
├─ 招商拓展 (recruit)              ← 新分组
│   ├─ 招商申请          admin/invest                 (新·占位)
│   └─ 意向池            admin/pool                   (新·占位)
├─ 财务中心 (finance)
│   ├─ 结算总览          admin/settle                 (新·占位)
│   ├─ 分账费率          admin/fee-config             (新·占位)
│   ├─ 钱包总览          admin/wallets
│   └─ 提现审核          admin/withdrawals            (badge: withdrawals)
├─ 合同中枢 (contract)             ← 新分组
│   └─ 平台合同管理      admin/contracts              (新·占位)
├─ 评价与反馈 (feedback)
│   ├─ 消息中心          admin/messages               (badge: messages)
│   └─ 评价与反馈中心    admin/feedback               (badge: feedback)
└─ 系统设置 (system)
    ├─ 区域管理          /regions
    ├─ 角色与权限        admin/roles
    ├─ 字体管理          admin/fonts
    ├─ 红线词库          admin/redline-words
    ├─ 操作日志          admin/audit-logs
    ├─ 账户详情          /account/profile
    └─ 系统设置          admin/settings
```

> 与三视角对齐点：内容审核/招商拓展分组命名与代理商视角完全一致；财务中心沿用 SP/代理商同名词；
> 评价与反馈沿用 SP/用户同组名；系统设置沿用总台既有。仅新增「合同中枢」一个治理专属分组。

## 4. 四大核心模块（占位页 + 未来接后端映射）

占位页统一采用 `AgentComingSoon` 组件（`apps/admin/src/pages/agentComingSoon.tsx`，已含 PageHead+Panel+「该功能即将上线」），

后续接后端时按「复用参考」迁移为真实页面。

### 4.1 平台合同管理 `admin/contracts`

- 占位：PageHead「平台合同管理」chip=「总台 · 全盘治理」+ 灰态卡片：主合同(MAIN)/代理协议(AGENCY) 统计、合同阶段(APPROVING/EFFECTIVE)、推进操作。
- 接后端：复用 `provider-console/contracts` 与 `agent-console/contracts` 的 Prisma `providerContract` 模型，

- 角标：后续加 `BadgeKey='contractPending'`（待推进合同数）。

### 4.2 服务审核 `admin/service-review` + 作品审核 `admin/work-review`

- 占位：两个菜单项，分别 PageHead「服务审核」「作品审核」+ 灰态卡片（待审队列、通过/驳回、红线分类）。
- 接后端：服务审核复用 `agent-console/templates`(review) 的 `reviewStatus` 过滤（去 regionPath=ALL）；

### 4.3 招商申请 `admin/invest` + 意向池 `admin/pool`

- 占位：PageHead「招商申请」「意向池」+ 灰态卡片（招商线索列表、阶段 WON/LOST、转化为入驻）。
- 接后端：复用 `agent-console/recruits`(`recruitLead` 模型) 新增 `admin/recruits`(GET 全量) + `PATCH stage` + `convert`。
参考 `apps/admin/src/pages/agentInvest.tsx`、`agentPool.tsx`。
- 角标：加 `investPending`（平台新招商数）。

### 4.4 结算总览 `admin/settle` + 分账费率 `admin/fee-config`

- 结算总览（已实现，非灰态）：复用 `AgentWallet` 组件 `variant="admin"`，零新增后端、复用 ALL 作用域 `agent/wallet` + `agent/providers` 端点。页面含 PageHead（标题「结算总览 · 全平台」+ chip「总台 · 全盘治理」）+ KPI（平台可提现总额 / 累计收入 / 已提现 / 全平台在营服务商）+ 全平台服务商钱包明细表，「查看」跳 `/admin/provider-review`。

- 接后端：结算总览复用 `agent-console/wallet`(辖区钱包聚合) 与 `admin/stats`；分账费率需新增
`admin/fee-config`(GET/PUT) 持久化费率规则（当前后端无此端点，接后端 Phase 新增）。参考 `apps/admin/src/pages/consolePages.tsx` 的 `AgentWallet`。

## 7. 风险与注意事项

1. **占位不伪造**：严格 `AgentComingSoon`；灰态卡片仅展示栏目名，绝不写死数据。
2. **GROUP_ORDER 全局共享**：改动仅影响总台视图内分组相对顺序，不破坏 agent/SP/user（其分组键不出现在总台）。
3. **权限串**：新资源 `permFor` 默认返回 `null`（可见）；若需 ADMIN 独占，补 `admin:*` 串并同步 `getAccess`。
4. **角标延迟**：占位期不挂 badge，避免 `useBadges` 返回 undefined 报错（组件已做 `badge??0` 兜底）。
5. **视察门控**：新页面组件（Phase 接后端时）须按 `isOwnView` 放行，不强制 subject。

## 8. 验收标准

- 总台菜单按 §3 树渲染，分组顺序、图标、折叠/角标交互与另外三视角完全一致。
- 7 个新菜单项点击均进入占位页（显示「该功能即将上线」），无 404、无白屏、typecheck 通过。
- 模板审核从「运营监管」移动到「内容审核」分组下，位置正确。
- 后续 Phase 接后端时，四大模块可零重构地复用对应 agent/SP 组件与端点（ALL 作用域）。
