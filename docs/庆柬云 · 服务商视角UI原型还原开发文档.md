# 庆柬云 · 服务商视角 UI 原型还原开发文档

> 用途：指导按本原型还原「服务商视角」的全部页面与功能模块（UI 界面 + 交互逻辑）。
> 依据：`UI_Design/index.html`（单文件管理后台原型，原生 JS + hash 路由，四视角共用一个文件，服务商视角为 `VIEW='provider'` 分支）；前台模板库效果参照同目录 `taklip.html`。
> 定位：一个后端 · 分层治理 · 总台统筹。服务商视角是四层角色中的业务核心层，数据作用域为自身（SELF），向上对接代理商/管理总台（资质、合同、消息、申诉），向下服务终端用户（接单、履约、评价、客户维护），是平台业务上下贯穿的中枢角色。

## 一、技术栈与还原约束

| 项 | 约定 |
| --- | --- |
| 框架 | 运营端 React 18 + Vite + Refine（@refinedev/antd）；本原型为单文件 HTML（原生 JS + hash 路由），还原时以 Ant Design 5 组件等价实现 |
| 组件库 | Ant Design 5：Table / Modal / Form / Select / Tabs / Tag / Input / DatePicker / Upload / Cascader / Timeline / Descriptions |
| 状态 | Zustand（视角 VIEW、当前页 PAGE、对象视角 CUR、各详情页编辑态 SVC_EDIT / TPL_EDIT / QUAL_EDIT / CTR_EDIT / TEAM_EDIT / CLT_EDIT / SCHED_EDIT / NTC_EDIT / MSG_EDIT / FB_VIEW） |
| 请求 | 运营端自定义 dataProvider 直连服务端 /api；原型数据为前端常量（PAGES / PROVIDERS / SVC_DICT），还原时替换为真实接口 |
| 数据隔离 | 服务商视角后端按登录主体注入数据作用域 SELF，原型所有列表副标题注明「数据隔离由后端强制」，列表只展示当前服务商自身数据 |
| 样式基准 | 主色 `--accent:#c24b2e`（朱砂暖陶红）、副色 `--accent-2:#14676b`（青）、页面底 `--page:#f5f2ec`（暖石底）、面板 `--bg:#fffefb`，状态标签五态（ok/warn/bad/ac/mut） |
| 图标 | 内联 SVG（desktop/package/stack/squares/star/file/clipboard/idcard/wallet/coins/bell/megaphone/users/building/house 等，Phosphor 风格线性图标） |
| 只读守卫 | `RO=true`（运维管理员代操作视角）时，服务商全部写操作（编辑/新建/接单/评价/互评/签署/触达）锁定并提示「当前为运维管理员（只读）视角」 |

## 二、服务商视角定位与能力

| 维度 | 说明 |
| --- | --- |
| 角色 | 入驻并通过审核的服务商主体（示例：麦麦提·艾力 SP001 · 喜事管家 · 特约设计 · 天山区），数据作用域自身（SELF） |
| 入口 | 顶部视角切换器「服务商视角」；总台管理员可切至服务商视角代查（默认只读 RO，超级管理员可写） |
| 顶部独有 | 「成为代理商」升格入口按钮（提交后置灰为「已提交 · 审核中」） |
| 账户胶囊 | 头像首字 + 昵称 + 服务商标签，下拉含快捷入口、待办事项、账号管理（账户详情） |
| 核心能力 | ① 供给经营：服务上架、模板发布（付费）、档期排期；② 订单履约：接单 → 履约 → 交付 → 评价（含互评追评）；③ 资质合同：业务申请、资质维护、在线签约；④ 财务：收入、提现、钱包；⑤ 消息：通知公告阅读留痕、业务消息互动与资料补填；⑥ 团队客户：角色化团队建设、客户精准维护触达 |

## 五、全局框架与视觉规范

### 5.1 整体布局

`.app` 为 `grid-template-columns:240px 1fr`（≤1180px 折叠为 64px 图标栏）：

- 左侧栏 `.side`（sticky 顶，高 100vh）：品牌区（Logo 渐变「庆柬云」+「管理后台」）→ 分组导航 `.nav`（.grp 分组标题 + .mi 菜单项 + .bdg 数字徽标）→ 底部 `.sidefoot`（头像 + 昵称 + 层级说明）。
- 右侧 `.main`：顶栏 `.top`（面包屑 crumb：`服务商中心 / 页面名` + 视角切换器 + 顶部操作区 + 账户胶囊）→ 页面区（`.page.on` 显示当前页）。

### 5.2 设计令牌（:root）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| --page / --bg / --panel-2 | #f5f2ec / #fffefb / #f3eee7 | 页面底 / 面板底 / 次级底 |
| --border | rgba(74,60,42,.10) | 分隔线（B 端靠线不靠阴影） |
| --ink-1 / --ink-2 / --ink-3 | #2a2118 / #4c4236 / #86765f | 主/次/弱文字 |

单元格/状态字段以 `#ok` / `#warn` / `#bad` / `#mut` / `#ac` 前缀开头，渲染为胶囊标签：

| 前缀 | 语义 | 典型文案 |

| #warn | 待处理/警示 | 待接单、待审核、未读、审核中、挂账中、待回应、待补材料 |
| #bad | 错误/驳回 | 已下架、已过期、已拒单、已驳回、已到期 |
| #mut | 中性/草稿 | 草稿、可接单、待激活、潜力客户、待签订 |
| #ac | 进行中/重点 | 履约中、已锁定、已互评、重点客户、审核中 |

## 七、通用列表页规范（pg-list）

### 7.1 渲染与事件分发

`renderList(key)` 读取 `PAGES[key]`：状态单元格按前缀渲染标签；金额列 `.num` 数字字体；行操作按 `PAGES[key].acts` 类型分发：

| acts | 行操作 | 点击行为 |
| --- | --- | --- |
| pord（我的订单） | 查看 + 接单/履约/评价（按状态动态命名，已评价置灰） | `openProcModal` |
| pfb（我的评价） | 查看 + 评价客户/追评（已互评后变「追评」） | `openEvCModal` |
| notice（通知公告） | 查看 | `openNoticeDetail`（详情页回写已读） |
| msg（业务消息） | 查看 | `openMsgDetail`（详情页回写已读） |
| edit / new | 查看 + 编辑（或新建按钮） | `openModal` → cfgPage 拦截链跳详情页 |
| clt（我的客户） | 维护 | `openCltCfg` |
| handle（意见反馈） | 处理/查看（按状态） | 详情页 pg-fbdetail 或弹窗 |
| 其他 | 查看 / 编辑 | `openModal` |

### 7.2 详情页拦截链（openModal）

当 `MODAL_META[key].cfgPage` 存在且操作为 edit/new 时，弹窗被替换为对应详情页：

| 列表页 | cfgPage | 详情页函数 |
| --- | --- | --- |
| p-services | pg-svccfg | openSvcCfg（新建/编辑） |
| p-templates | pg-tplcfg | openTplCfg（新建/编辑） |
| p-qualification | pg-qualc | openQualCfg（编辑） |
| p-contract | pg-ctrcfg | openCtrCfg（编辑） |
| p-team | pg-teamcfg | openTeamCfg（新建/编辑） |
| p-clients | pg-cltcfg | openCltCfg（编辑） |
| p-schedule | pg-schedcfg | openSchedCfg（新建/编辑） |
| p-notices / p-messages | detailPage | openNoticeDetail / openMsgDetail |

### 7.3 财务统计卡（finStat）

仅 `VIEW==='provider'` 渲染，插入到列表面板头部（`#listPanelHead` 之后）：

| 页面 | 统计口径 | 展示项 |
| --- | --- | --- |
| p-wallet 我的钱包 | 入账（类型含「入账」且状态「已入账」）累加、挂账累加、提现绝对值累加 | 累计入账 ¥2,860 / 挂账待结 ¥520 / 提现审核中 ¥800 / 预计可提现 ¥1,540（= 入账-挂账-提现） |

### 7.4 四态页

`pg-states`：空态（暂无待处理数据 + 新建按钮）、加载态、错误态、骨架态四套面板，供列表/详情加载兜底。

## 八、服务商 16 项菜单页面逐一说明

> 通用列表字段格式：`列名（列索引）`；状态列 `fcol` 用于筛选与状态标签。所有列表数据为原型样例，还原时以真实接口返回替换。

### 8.1 我的订单（p-orders · 订单履约）

- 副标题：接单 / 履约 / 交付；chip「服务商 · 特约设计」；筛选：全部/待接单/履约中/已完成；fcol=4。
- 列：订单号(0) / 用户(1) / 服务(2) / 金额(3) / 状态(4) / 时间(5)。
- 样例：QJ202608270013 刘倩 摄影摄像 ¥1,280 待接单；QJ202608270011 张伟 婚庆主持 ¥880 履约中；QJ202608260098 热依汗 花艺布置 ¥520 已完成。
- 行操作按钮命名规则：已评价→「已评价」（置灰）／待接单→「接单」／履约中→「履约」／已完成→「评价」。
- **三态处理弹窗 `openProcModal`**（共用 `#mKv`，显式 `display:block` 防标签重叠；弹窗头固定为「订单号 · 服务 / 用户 · 金额」信息行）：

| 订单状态 | 弹窗标题 | 表单区 | 底部按钮 |

## 九、详情页标准化布局规范（服务商专用模板）

所有服务商详情页（pg-svccfg / pg-tplcfg / pg-qualc / pg-ctrcfg / pg-teamcfg / pg-cltcfg / pg-schedcfg）统一遵循以下模板：

```
section.page
├─ .pghead：h2 标题（新建态为「新建…」）+ .sub 副标题（编辑态含「编辑「名称」…」）+ ← 返回列表按钮
└─ .svcf-grid（grid: 1fr 360px，两列）
   ├─ 左列：表单面板组（自上而下）
   │   ├─ .panel 基本信息（编号只读 + 必填核心字段，.svcc-row 双列 + .svcc-field 单列）
   │   ├─ .panel 展示/业务配置（色板 .svcc-sw / 多选 .svcc-chips / 类型卡 .type-grid）
   │   ├─ .panel 价格与数据（金额/数量/评分，带校验区间提示）
   │   ├─ .panel 内容说明（textarea + 字数 hint）
   │   └─ 底部操作区（保存草稿 / 保存并上架等主按钮）
   └─ 右列：预览与信息面板组
       ├─ .panel 前台/对外预览（实时同步 · 复刻前台卡片样式）
       ├─ .panel 流程/规则/模型（时间轴或规则列表）
       └─ .tipbox 口径提示（ℹ️ 字段口径与业务申请页一致等）
```

通用交互约定：

1. **实时预览**：左列任一输入（oninput/onchange/色板点击/chips 点击）立即驱动右列预览重渲染。
2. **编辑态回填**：`openXxxCfg` 按行数组索引回填；新建态自动生成编号（SV-/T-/ZZ-/HT-/MT-/SC-/PC- 规则取前缀 + 当前最大序号 + 1）。
3. **RO 守卫**：所有详情页入口在 RO 时 alert 拦截。
4. **返回**：返回按钮与取消按钮均 `goPage(编辑页 key)` 回到来源列表。
5. **保存校验**：`validateXxxForm` 逐项校验必填与区间，失败 alert 并中止；成功后写回 `PAGES[key].r` → `renderList` → `goPage` → alert 结果提示。

## 十、核心交互与业务规则清单

### 10.1 订单履约闭环（待接单 → 履约中 → 已完成 → 已评价）

```
用户下单 → 待接单(服务商确认接单/拒绝)
   → 履约中(维护进度记录 · 完成交付)
   → 已完成(服务商评价订单；可追评)
   → 已评价(行按钮置灰)
```

- 接单必填预计服务时间；拒单置「已拒单」。
- 履约维护写进度说明（正常履约/待补充素材/已交付待验收）；完成交付后等待客户确认与评价。
- 评价/追评 5 星 + 评语，写 r[6..8]。

### 10.2 服务商与用户互评

- 用户视角「评价服务商」（u-orders/u-providers）与服务商视角「评价客户」（p-feedback）构成互评；双方均完成评价后公开展示。
- 服务商侧已互评 → 行按钮「评价客户」变「追评」；追评回填原评语并可修改星级，提交后更新时间戳 r[8]。

### 10.3 阅读行为回写（通知公告 / 业务消息）

- 进入详情页即 `markRead`：状态含「未读」→ 置「#ok 已读」并 `renderList` 刷新列表状态。
- 通知公告：查看即已读；附件支持预览/下载。
- 业务消息：查看即已读；支持与发送方互动（会话气泡 + 发送回复）与资料补填（待补材料提示 + 提交资料）。

### 10.4 档期冲突检测与订单联动

- 冲突规则：同日同时段仅允许一个「已锁定」档期；「全天」与任一时段互斥；「已完成」「可接单」不参与冲突。
- 日期归一化：保存与检测两侧统一 `replace(/^\d{4}-/,'')`，兼容 MM-DD / YYYY-MM-DD 输入。
- 联动：档期选择关联订单自动回填客户/服务类型并置「已锁定」；接单自动锁定档期、交付完成释放。

### 10.5 财务口径

- 金额解析 `parseAmt`（取首个数字串，去千分位）；统计按类型+状态聚合（入账=「入账」+「已入账」；挂账=「挂账」；提现=「提现」绝对值）。
- 预计可提现 = 累计入账 − 挂账待结 − 提现审核中（≥0）。
- 结算周期 T+3；提现不可超过钱包可提现余额。

### 10.6 合同在线签署流程

```
草拟协商（多轮 · 记录留痕）
  → 服务商在线签署（短信验证 + 手写签名）
  → 代理商/管理总台审批签署
  → 生效归档（到期前 30 天提醒续签）
```

- 签署阶段机：待协商/协商中/待服务商签署/待上级签署/审批中/已生效/已到期/已终止；仅「待服务商签署」「已生效」可发起在线签署。
- 甲方选择决定审批链（管理总台 / 辖区代理商）。

### 10.7 团队最小授权

- 数据作用域三档：自身 / 自身（服务域）/ 本服务商，权限「不超自身」。
- 功能权限按角色授予（8 项）；服务类型切换联动角色候选池、职责池、个性特征与角色模型。

### 10.8 客户维护「精准不扰」

- 四类触达：服务消息 / 优惠券 / 优惠活动 / 答谢奖励服务；渠道：站内信/短信/微信/电话。
- 权益类需填面额与有效期；保存即推送客户消息中心，触达记录自动留痕（时间轴）。

### 10.9 反馈升级链

- 服务商意见反馈 → 服务商负责人 → 升级代理商 → 平台仲裁（服务商/代理商/平台自下而上）。
- 反馈详情全程留痕，可补充消息。

## 十三、还原边界与遗留说明

1. **RO 只读守卫**：服务商视角写操作均受 `RO` 控制，还原时以登录角色权限映射替代（服务商本体可写、运维代查只读）。
2. **原型提示占位**：上传、下载、在线签署、电子签章、短信/微信触达等均为 `alert` 原型占位，还原时接入真实文件服务 / 电子签章服务 / 消息推送通道。
3. **静态样例数据**：PAGES / PROVIDERS / SVC_DICT 为前端常量；还原时替换为 /api 接口，保持字段索引口径一致（见第八、十一章）。
4. **弹窗布局防重叠**：订单/评价/互评类弹窗的 `#mKv` 容器必须显式 `display:block`（禁用默认两列 grid），避免信息行与表单区块重叠——这是已修复的历史缺陷，还原时需回归验证。
5. **前台联动**：服务/模板「保存并上架/发布」后，前台 taklip.html 服务专区与模板库即时同步，需前后台接口打通。
