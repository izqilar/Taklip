## 1. 改造背景与目标

当前用户端（`apps/web`）登录页仅支持 **「手机号 + 密码」** 单一方式，且无任何「忘记密码」入口，用户一旦遗忘密码即被永久锁死，只能联系人工。这与「让非技术用户也能顺畅使用」的产品定位不符，也弱于主流平台的多方式登录体验。

**本次改造目标：**

| 编号 | 目标 | 类型 | 优先级 |
|------|------|------|--------|
| G-1 | 登录标识扩展：支持 **用户 ID / 邮箱 / 用户名（昵称）** 作为账号登录 | 功能 | P0 |
| G-2 | 新增 **微信扫码** 登录（网站应用 OAuth2） | 功能 | P0 |
| G-3 | 新增 **QQ 扫码** 登录（QQ 互联 OAuth2） | 功能 | P1 |
| G-4 | 新增 **忘记密码 / 重置密码 ** 自助恢复入口和 | 功能 | P0 |
| G-5 | 登录页支持「账号+密码」「手机验证码」「扫码」多入口切换 | 体验 | P1 |
| G-6 | 安全加固：防账号枚举、限流、OAuth state 防 CSRF、重置令牌防泄露 | 安全 | P0 |

> ⚠️ **范围边界**：本改造**不改变**「统一登录落点」（`ROLE_HOME`，见附录 A）与「Web→Admin SSO 票据桥接」（`/api/auth/ticket`、`/api/auth/exchange`）的既有范式，仅在此之上扩展登录**来源**。所有新登录方式最终都必须调用既有的 `generateTokens()` 以返回一致的 `home` 落点，否则会出现「登录成功但跳错工作台」的回归。

## 2. 现状盘点（基于代码核查）

> 以下结论均来自对仓库的只读核查，改造须以此为真值基准。

### 2.1 当前登录方式

- **Web 登录页**：`apps/web/src/pages/Login.tsx`（头部注释即 `登录页 — 手机号 + 密码登录`）。表单仅两个字段：`phone`（`type=tel`，`pattern=1\d{10}`）+ `password`（`minLength=6`），提交走 `useAuthStore.login(phone, password)`。
- **服务端登录**：`apps/server/src/auth/auth.service.ts` `login(dto)` → `prisma.user.findUnique({ where: { phone } })`，再 `bcrypt.compare(password, user.password)`。
- **登录 DTO**：`apps/server/src/auth/dto/auth.dto.ts` `LoginDto` 仅 `phone!` + `password!`。

### 2.2 User 模型标识字段现状

`apps/server/prisma/schema.prisma` 第 85–164 行 `model User`：

| 字段 | 约束 | 能否作为唯一登录标识 | 备注 |
|------|------|------------------|------|
| `id` | `@id @default(cuid())` | ✅ 可（天然唯一） | 即「用户 ID」 |
| `phone` | `String? @unique` | ✅ 可 | 当前唯一在用登录标识 |
| `email` | `String?`（**无 @unique**） | ❌ 当前不可 | 需加 `@unique` 才能做登录键 |
| `nickname` | `String?`（无唯一） | ❌ 不可（可能重名） | 「昵称」非唯一，直接作登录键会歧义 |
| `realName` | `String? @map("real_name")`（无唯一） | ❌ 不可 + 隐私敏感 | 真实姓名非唯一且属 PII，**不建议作登录键** |
| `wxOpenid` | `String? @unique` | ✅ 可（已存在，闲置） | 微信登录可直接复用 |
| `qqOpenid` | **不存在** | ❌ 需新增 | QQ 登录需新增 `@unique` 列 |
| `password` | `String?`（bcrypt 哈希，可空） | — | 空值 = 纯第三方账号（无密码） |

### 2.3 密码与重置现状

- **哈希**：`bcrypt`，`SALT_ROUNDS = 10`（`auth.service.ts:21`）。注册哈希、登录比对、改密均走 bcrypt。
- **改密（需登录态）**：`POST /api/auth/change-password`（`ChangePasswordDto`：`oldPassword`+`newPassword`）。**必须已知旧密码**。
- **找回密码 / 重置流程**：**完全缺失**。全仓库 `apps/server/src` 下 grep `resetPassword|passwordReset|forgot|验证码` **零命中**；schema 无 `resetToken`/过期字段；**无邮件 / SMS 发送逻辑**。

### 2.4 第三方登录现状

- 服务端**仅一个** Passport 策略：`jwt.strategy.ts`（`AuthGuard('jwt')`）。无任何 OAuth2 / 微信 / QQ 策略，无 `redirect`/`callback` 路由。
- `User.wxOpenid` 与 `UserInfo.wxOpenid` 仅是预留占位列，未被任何登录路径消费。
- 全仓库命中 `WeChat/weixin/qq` 的内容均为无关业务（营销触达渠道枚举 `ProviderClientReach.channel`、tailwind 颜色等）。

### 2.5 限流 / 安全现状

- `RateLimitGuard`：login 20 次/分、register 5 次/分（内存计数）。新增端点须复制该守卫。
- 多实例下 `tickets` Map（SSO 票据）与限流计数仍驻内存 —— 代码注释已注明应迁 Redis。本项目 **Redis 已就位**，改造第三方扫码轮询态、重置令牌、限流计数建议统一迁 Redis。

## 3. 改造方案总览

### 3.1 多方式登录矩阵

| 登录方式 | 标识字段 | 凭证 | 改造要点 | 优先级 |
|---------|---------|------|---------|--------|
| 手机号 + 密码 | `phone` | 密码 | 保留现状 | — |
| 手机号 + 验证码 | `phone` | SMS 验证码 | **依赖短信网关**（见 §12 D1） | P1 |
| 用户 ID + 密码 | `id` | 密码 | `id` 天然唯一，直接可用 | P0 |
| 邮箱 + 密码 | `email` | 密码 | **schema 加 `@unique`**（见 §4） | P0 |
| 用户名/昵称 + 密码 | 新增 `username` | 密码 | 见 §12 D2（推荐新增专用唯一登录名） | P0 |
| 微信扫码 | `wxOpenid` | OAuth2 code | 复用 `wxOpenid`，新增扫码流程（§5.3） | P0 |
| QQ 扫码 | `qqOpenid` | OAuth2 code | **schema 新增 `qqOpenid`**（§4）+ 流程（§5.4） | P1 |

> **关于「昵称」「真实姓名」的处理（重要）：**
>
> - **昵称（nickname）非唯一**，若直接作登录键会出现「多个用户重名 → 无法定位唯一账户」。方案见 §12 D2：推荐新增一个**专用的、唯一的 `username`（登录名/用户名）**字段承接「昵称登录」语义，`nickname` 继续作为展示名（可重名）。
> - **真实姓名（realName）**：非唯一且属 **PII（个人敏感信息）**，**不建议作为登录标识**。若确有业务诉求，仅可作为「辅助验真因子」（配合手机/邮箱二次确认），**绝不能单独作为登录键**。本方案默认**不将其纳入登录标识**，列为评审决策 D3。

### 3.2 密码找回 / 重置流程（G-4）

采用 **「令牌（token）+ 联系渠道送达 + 重设密码」** 标准范式：

```
用户点击「忘记密码？」
  → 进入 /forgot-password 页，输入「手机号 / 邮箱 / 用户ID / 用户名」任意一种
  → POST /api/auth/forgot-password { identifier }
       服务端定位账户（防枚举：账户不存在也返回「若账户存在，重置凭证已发送」）
       生成单次使用重置令牌（随机 + 哈希存储，TTL 30 分钟）
       通过渠道送达：有 email → 发重置邮件(含链接)；有 phone → 发 SMS 验证码
  → 用户凭邮件链接 / 短信验证码 + 新密码
  → POST /api/auth/reset-password { token(或 code), newPassword }
       校验令牌/验证码 + 未过期 + 未使用 → 更新 password(bcrypt) → 作废令牌
  → 提示「密码已重置，请重新登录」
```

**关键约束（详见 §10）：**
- 重置令牌**哈希存储**（不存明文）、**单次使用**、**TTL 30 分钟**。
- 纯第三方账号（`password` 为空）无密码可重置；此类用户须先走「设置密码」绑定流程（见 §12 D4），或改用第三方扫码登录。
- 渠道发送依赖外部能力（邮件 SMTP / 短信网关），当前服务端**完全缺失**该能力 → 这是 **P0 前置依赖**（见 §12 D1）。

## 4. 数据层改造（Prisma Schema + 迁移）

> 迁移走项目既有「手写 migration.sql → `prisma db execute` → `prisma migrate resolve --applied` → `prisma generate`」铁律（见附录 A），**禁止 `prisma migrate dev`**。

### 4.1 User 模型变更

```prisma
model User {
  // —— 既有字段保留 ——
  id       String   @id @default(cuid())
  phone    String?  @unique
  wxOpenid String?  @unique

  // —— 4.1.1 email 加唯一约束（G-1 邮箱登录前提）——
  email    String?  @unique

  // —— 4.1.2 新增 QQ openid（G-3）——
  qqOpenid String?  @unique

  // —— 4.1.3 新增专用唯一登录名（G-1 昵称/用户名登录，见 D2）——
  username String?  @unique

  password String?  // 可空：纯第三方账号无密码

  // —— 4.1.4 重置令牌（G-4，也可独立模型，见 4.2）——
  resetTokenHash   String?   @map("reset_token_hash")
  resetTokenExpiry DateTime? @map("reset_token_expiry")
  resetTokenUsed   Boolean   @default(false) @map("reset_token_used")

  // ……其余既有字段保持不变……
}
```

### 4.2 密码重置令牌：列内 vs 独立模型（决策 D5）

- **方案 A（上表 4.1.4）**：在 `User` 上挂 `resetTokenHash/Expiry/Used`。简单、无需联表；缺点：一个用户同时只能有一个有效重置请求（可接受）。
- **方案 B**：独立 `PasswordReset { id, userId, tokenHash, expiresAt, used, channel }`。支持并发多渠道、审计更清晰。
- **推荐方案 A**（最小改动、够用），D5 留待评审。

### 4.3 迁移 SQL 草拟（示意）

```sql
-- 1. email 加唯一
CREATE UNIQUE INDEX IF NOT EXISTS "User_email_key" ON "User"("email") WHERE "email" IS NOT NULL;
-- 2. 新增 qqOpenid + 唯一
ALTER TABLE "User" ADD COLUMN "qq_openid" TEXT;
CREATE UNIQUE INDEX IF NOT EXISTS "User_qqOpenid_key" ON "User"("qq_openid") WHERE "qq_openid" IS NOT NULL;
-- 3. 新增 username + 唯一
ALTER TABLE "User" ADD COLUMN "username" TEXT;
CREATE UNIQUE INDEX IF NOT EXISTS "User_username_key" ON "User"("username") WHERE "username" IS NOT NULL;
-- 4. 重置令牌列
ALTER TABLE "User" ADD COLUMN "reset_token_hash" TEXT;
ALTER TABLE "User" ADD COLUMN "reset_token_expiry" TIMESTAMP(3);
ALTER TABLE "User" ADD COLUMN "reset_token_used" BOOLEAN NOT NULL DEFAULT false;
```

> 注意：存量 `email` 若存在重复值，`CREATE UNIQUE INDEX` 会失败 → 迁移前须先 `SELECT email, count(*) FROM "User" GROUP BY email HAVING count(*)>1` 清洗重复（或脚本合并/置空）。

## 5. 服务端改造（auth 模块）

### 5.1 DTO 重构（auth.dto.ts）

**废弃**单一 `LoginDto`（仅 phone），改为「标识 + 密码」通用登录：

```typescript
// 登录方式类型
export type LoginIdentifierType = 'phone' | 'email' | 'userId' | 'username';

export class LoginDto {
  @IsEnum(LoginIdentifierType)
  type!: LoginIdentifierType;     // 标识类型，前端按输入框选择/自动识别

  @IsString()
  @MinLength(1)
  account!: string;               // 对应 type 的标识值

  @IsString()
  @MinLength(6)
  @MaxLength(64)
  password!: string;
}
```

> 备选：不显式传 `type`，由服务端对 `account` 做**智能识别**（含 `@` → email；纯数字 11 位 → phone；cuid 形态 → userId；其余 → username）。本方案推荐**显式 `type`**（前端用分段/下拉，体验更可控且避免歧义），D6 评审。

**新增 DTO：**

```typescript
export class ForgotPasswordDto {
  @IsString() @MinLength(1)
  identifier!: string;            // phone / email / userId / username 任一
}

export class ResetPasswordDto {
  @IsString() @MinLength(1)
  token!: string;                 // 邮件链接令牌 或 SMS 验证码
  @IsString() @MinLength(6) @MaxLength(64)
  newPassword!: string;
}
```

### 5.2 登录解析逻辑（auth.service.ts `login` 改造）

```typescript
async login(dto: LoginDto) {
  const where = {
    phone:   dto.type === 'phone'   ? dto.account : undefined,
    email:   dto.type === 'email'   ? dto.account : undefined,
    id:      dto.type === 'userId'  ? dto.account : undefined,
    username:dto.type === 'username'? dto.account : undefined,
  };
  const user = await this.prisma.user.findFirst({ where });
  if (!user || !user.password) throw new UnauthorizedException('ACCOUNT_OR_PASSWORD_INVALID'); // 防枚举：统一文案
  if (user.status === 'DISABLED') throw new ForbiddenException('ACCOUNT_DISABLED');
  const ok = await bcrypt.compare(dto.password, user.password);
  if (!ok) throw new UnauthorizedException('ACCOUNT_OR_PASSWORD_INVALID');
  await this.prisma.user.update({ where:{ id:user.id }, data:{ lastLoginAt:new Date() }});
  return this.generateTokens(user);   // 复用既有落点逻辑，保证 home 一致
}
```

> `findUnique` 在 `email/username` 加 `@unique` 后可用于唯一查找；`userId` 用 `id` 主键查找。统一异常文案 `ACCOUNT_OR_PASSWORD_INVALID` 防止账号枚举（§10 高）。

### 5.3 微信扫码登录（G-2）

**流程（微信开放平台「网站应用」扫码登录，OAuth2）：**

```
1. 前端 → POST /api/auth/wechat/qr/start
   服务端生成 state(随机) + 记录 pending 态到 Redis(key=wechat:qr:${state}, TTL=5min)
   返回: { state, qrcodeUrl }
        qrcodeUrl = https://open.weixin.qq.com/connect/qrconnect
                    ?appid=${WX_APPID}&redirect_uri=${encodeURIComponent(CB)}&response_type=code
                    &scope=snsapi_login&state=${state}
2. 前端将 qrcodeUrl 渲染为二维码，并轮询 GET /api/auth/wechat/qr/status?state=xxx
3. 用户手机微信扫码并确认 → 微信重定向到 redirect_uri?code=CODE&state=STATE
4. 服务端 /api/auth/wechat/callback?code&state
   → code 换 access_token + openid (https://api.weixin.qq.com/sns/oauth2/access_token)
   → 用 openid 查找/创建用户(wxOpenid)；新用户走「第三方静默注册」(password=null, role=USER)
   → 签发 JWT，把 { accessToken, ... } 写入 Redis(wechat:qr:${state}) 并标记 done
5. 前端轮询拿到 done + token → 本地落地登录态，跳 home
```

- `state` 参数**必须校验回放**（防 CSRF），且一次性。
- 复用 `generateTokens()` 返回 `home`。
- 配置：`WX_APPID` / `WX_APPSECRET` / `WX_REDIRECT_URI` 走环境变量（**严禁硬编码**）。

### 5.4 QQ 扫码登录（G-3）

与微信同构，基于 **QQ 互联「网站应用」扫码登录**（OAuth2）：

- 新增 `qqOpenid` 列（§4.1.2）。
- 端点：`/api/auth/qq/qr/start`、`/api/auth/qq/qr/status`、`/api/auth/qq/callback`。
- 用 `code` 换 `access_token`（https://graph.qq.com/oauth2.0/token）→ 换 `openid`（https://graph.qq.com/oauth2.0/me）→ 取 `userinfo`。
- 配置：`QQ_APPID` / `QQ_APPKEY` / `QQ_REDIRECT_URI` 环境变量。
- 同样 state 校验 + Redis pending 态 + 复用 `generateTokens()`。

### 5.5 密码找回 / 重置（G-4）

```typescript
// forgot-password：定位账户并发送凭证
async forgotPassword(dto: ForgotPasswordDto) {
  const user = await this.resolveByIdentifier(dto.identifier); // 同 5.2 解析
  // 防枚举：无论是否找到都返回成功文案
  if (user) {
    const token = randomBytes(32).toString('hex');
    const hash = sha256(token);
    await this.prisma.user.update({ where:{id:user.id}, data:{
      resetTokenHash: hash, resetTokenExpiry: addMinutes(30), resetTokenUsed:false }});
    await this.notifyReset(user, token); // 发邮件 / SMS（依赖 D1 渠道）
  }
  return { message: '若账户存在，重置凭证已发送' };
}

// reset-password：校验并落库新密码
async resetPassword(dto: ResetPasswordDto) {
  const user = await this.prisma.user.findFirst({ where:{ resetTokenHash: sha256(dto.token) }});
  if (!user || user.resetTokenUsed || !user.resetTokenExpiry || user.resetTokenExpiry < new Date())
    throw new BadRequestException('RESET_TOKEN_INVALID');
  await this.prisma.user.update({ where:{id:user.id}, data:{
    password: await bcrypt.hash(dto.newPassword, 10),
    resetTokenUsed: true, resetTokenHash: null, resetTokenExpiry: null }});
}
```

> **令牌安全（§10 严重）**：仅存 `sha256(token)`（不可逆），明文 token 只通过渠道一次性下发；TTL 30 分钟；`used` 单次作废。SMS 验证码模式同理（验证码服务端哈希 + TTL + 限尝试次数）。

### 5.6 安全与限流

- **复用 `RateLimitGuard`** 并扩展：`forgot-password`(5 次/分)、`reset-password`(10 次/分)、`wechat/qr/start`/`qq/qr/start`(10 次/分)。
- **重置尝试次数限制**：`reset-password` 连续失败 N 次锁定该令牌（防爆破）。
- **Redis 化**：二维码 pending 态、重置令牌元数据、限流计数统一迁 Redis（多实例安全），复用既有 Redis。

## 6. 前端改造（apps/web 登录页 + 找回页）

### 6.1 登录页 `apps/web/src/pages/Login.tsx` 重构

- **多入口切换**（分段控件 / Tab）：

## 8. 接口定义（请求/响应契约）

> 既有约定：`/api/auth/*` 前缀；Bearer Token 鉴权；错误用 HTTP 状态码 + 业务码（沿用 `errors.*`）。以下为新增/变更端点。

### 8.1 通用密码登录（变更）

```
POST /api/auth/login
{ "type": "phone|email|userId|username", "account": "13800138000", "password": "******" }
→ 200 { accessToken, refreshToken, expiresIn:7200, user, home }   // 复用 AuthResponse
→ 401 { code, message:"ACCOUNT_OR_PASSWORD_INVALID" }
```

### 8.2 微信扫码

```
POST /api/auth/wechat/qr/start      → { state, qrcodeUrl }
GET  /api/auth/wechat/qr/status?state=xxx
                                    → { status:"pending|scanned|done", token?:{accessToken,...} }
GET  /api/auth/wechat/callback?code=CODE&state=STATE   （微信重定向，服务端内部消费）
```

### 8.3 QQ 扫码

```
POST /api/auth/qq/qr/start          → { state, qrcodeUrl }
GET  /api/auth/qq/qr/status?state=xxx
GET  /api/auth/qq/callback?code=CODE&state=STATE
```

### 8.4 忘记 / 重置密码

```
POST /api/auth/forgot-password      { "identifier": "13800138000 | a@b.com | usr_xxx | loginname" }
                                    → { message:"若账户存在，重置凭证已发送" }

POST /api/auth/reset-password       { "token": "hex-or-code", "newPassword": "******" }
                                    → 200 { message:"密码已重置" }
                                    → 400 { code, message:"RESET_TOKEN_INVALID" }
```

## 10. 安全与正确性分级（严重 / 高 / 中 / 低）

| 级别 | 项 | 描述与最小修复 |
|------|----|--------------|
| 🔴 严重 | 重置令牌明文存储 | 必须仅存 `sha256(token)`，明文不落库；TTL+单次作废 |
| 🔴 严重 | OAuth `state` 缺失/不校验 | 微信/QQ 必须生成随机 `state`、Redis 记录、回调校验回放，防 CSRF 账号绑定劫持 |
| 🔴 严重 | 第三方账号空密码越权 | `password=null` 的微信/QQ 账号走 `login` 须直接拒绝密码登录（5.2 已挡），且不可被 reset 设置后绕过 |
| 🟠 高 | 账号枚举 | `login`/`forgot-password` 统一文案「账号或密码错误 / 若账户存在…」，不泄露账户是否存在 |
| 🟠 高 | 限流缺失 | 新端点必须挂 `RateLimitGuard`，重置尝试加失败计数锁定 |
| 🟠 高 | `email` 唯一约束迁移失败 | 迁移前清洗重复 email，否则 `CREATE UNIQUE INDEX` 失败阻塞部署 |
| 🟡 中 | 多实例状态不一致 | 二维码 pending 态 / 重置元数据 / 限流计数迁 Redis（已有 Redis） |
| 🟡 中 | 真实姓名作登录键 | 默认不纳入；若强需求仅作辅助验真因子，防 PII 泄露 |
| 🟡 中 | 昵称重名歧义 | 用专用 `username` 承接登录语义，nickname 保持展示名 |
| 🟢 低 | 前端输入框回填 | 邮件链接 `?token=` 自动填入重置页；登录失败保留已输入账号 |
