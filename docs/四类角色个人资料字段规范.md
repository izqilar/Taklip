# 四类角色个人资料字段规范

> 对系统管理员、代理商、服务商、注册客户四类角色的个人资料字段做统一规范梳理（仅字段定义，不涉及界面设计）。

---

## 一、个人资料字段的通用分层

所有角色的个人资料可统一归为七层，便于后续在「个人中心 / 资料编辑」中组织：

| 层级 | 包含内容 | 说明 |
|---|---|---|
| ① 基础身份 | ID、姓名 / 名称、头像、昵称 | 唯一标识与展示名 |
| ② 联系信息 | 手机号、邮箱 | 原型仅实现手机号 |
| ③ 归属与作用域 | 角色、所属区域 / 辖区、数据作用域 | 决定可见菜单与数据范围 |
| ④ 业务属性 | 职能角色（管理员）/ 服务类型（服务商）/ 会员等级（客户）/ 辖区（代理商） | 各角色特有 |
| ⑤ 资质与认证 | 资质项列表（服务商）、实名认证 | 仅服务商有显式资质 |
| ⑥ 账户状态 | 状态、注册 / 提交时间、最后登录 | 状态机驱动 |
| ⑦ 资产与权益 | 余额、积分、累计消费（客户）；钱包（代理 / 服务商） | 衍生账户数据 |

---

## 二、四类角色个人资料字段明细

### 1. 系统管理员（ADMIN）

原型中管理员没有独立的个人资料页，仅在「用户管理」中以通用用户记录出现，在「角色与权限」中以职能角色定义出现。

| 字段 | 原型状态 | 说明 |
|---|---|---|
| 用户 ID | ✅ 已实现 | 如 张敏 对应记录 |
| 姓名 | ✅ 已实现 | 用户管理页「用户」列 |
| 手机号 | ✅ 已实现 | 用户管理页「手机号」列 |
| 头像 | ⚠️ 未显式 | 原型管理员记录无头像 |
| 昵称 | ⚠️ 未显式 | 原型无 |
| 邮箱 | ❌ 缺失 | 建议补充 |
| 角色 | ✅ 已实现 | 固定为「管理员」 |
| 所属区域 | ✅ 已实现 | 固定为「总部」 |
| 数据作用域 | ✅ 已实现 | 全平台（ALL） |
| 职能角色 | ✅ 已实现 | 超级管理员 / 运维管理员 / 服务审核员 / 财务管理员 / 在线客服 |
| 权限位阶 | ✅ 已实现 | 100→60 五级 |
| 功能权限集合 | ✅ 已实现 | 10 域 28 点 |
| 勾选状态 | ✅ 已实现 | 正常 / 停用 |
| 注册时间 | ✅ 已实现 | 用户管理页 |
| 工号 / 部门 | ❌ 缺失 | 建议补充（企业属性） |
| 最后登录时间 | ❌ 缺失 | 建议补充（安全审计） |

**管理端可编辑范围**：仅「角色、所属区域、状态」（用户管理编辑对话框）；职能角色与权限在「角色与权限」页单独维护。

## 三、共性与差异总结

| 维度 | 系统管理员 | 代理商 | 服务商 | 注册客户 |
|---|---|---|---|---|
| 基础身份（ID / 姓名 / 手机） | ✅ | ✅ | ✅ | ✅ |
| 头像 | ❌ | ❌ | ❌ | ✅ |
| 昵称 | ❌ | ✅ | ✅ | ❌ |
| 归属区域 | 总部 | 辖区 | 区域 | 城市 |
| 特有业务属性 | 职能角色 + 权限位阶 | 辖区 | 服务类型 + 资质 | 会员等级 |
| 资质认证 | 无 | 无（建议补营业执照） | 多项资质 | 无（建议补实名） |
| 资产 | 无 | 钱包 | 钱包 + 冻结 | 余额 + 积分 + 消费 |
| 管理端可编辑 | 角色 / 区域 / 状态 | 名称 / 辖区 / 状态 | 审核意见 / 服务 / 资质 | 角色 / 区域 / 状态 / 等级测试 |

## 四、原型覆盖度说明

### 已完整实现
四类角色的基础身份（ID / 姓名 / 手机）、归属与作用域、状态、注册时间，以及各角色特有业务属性（职能角色 / 辖区 / 服务类型 + 资质 / 会员等级）。

### 部分实现
- 头像（仅客户）
- 昵称（代理 / 服务商有但列表未展示）
- 资产（均有衍生展示但无独立资料页）

### 统一缺失
- 邮箱、最后登录时间
- 管理员 / 代理商 / 服务商的头像
- 客户的昵称 / 性别 / 生日 / 地址
- 代理商的营业执照 / 联系人
- 服务商的身份证 / 紧急联系人

### 管理端编辑范围说明
管理端对个人资料的可编辑字段主要是「管理属性」（角色、区域、状态、审核意见），基础身份信息（姓名、手机号）均为只读 —— 这符合「用户自行维护基础资料、管理端只管控治理属性」的常规设计。若后续需要管理端代填 / 代改，需单独扩展。
