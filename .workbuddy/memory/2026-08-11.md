## 编辑器白屏 Bug 修复（紧急情况）

### 现象
- 用户反馈：localhost:5173 点击「婚礼请柬 → 立即制作」进入编辑器后，点击画布上任意对象（文本/图形）即整页变白，仅刷新可恢复。

### 根因
1. **白屏崩溃（核心）**：`PropertyPanel.tsx` 的 `FieldRenderer` 在 `slider`/`number` 分支直接对属性值调用 `.toFixed()` / `Math.round()`。模板/旧作品的某些元素缺少 `opacity`/`rotation` 等字段默认值（运行时值为 `undefined`），导致 `TypeError: Cannot read properties of undefined (reading 'toFixed')`。React 无 Error Boundary，未捕获渲染异常使整棵组件树卸载 → 白屏。
2. **React key 警告**：`EditorCanvas.tsx` 将 `key: el.id` 放入 `common` 对象并通过 `{...common}` 展开到 Konva 元素上，违反 React 规则（key 不可经 spread 传入），触发 "A props object containing a 'key' prop is being spread into JSX" 警告。
3. **3 位十六进制颜色警告**：`<input type="color">` 要求 `#rrggbb`，模板中 `#666` 等 3 位值被拒绝并告警。

### 修复
- `apps/web/src/components/Panel/PropertyPanel.tsx`：
  - `number` 分支：`value={Number.isFinite(value) ? value : 0}`
  - `slider` 分支：统一兜底 `const num = Number.isFinite(value) ? value : 0`，显示按 step 决定 `toFixed(2)`/`Math.round`
  - `color` 分支：3 位 `#rgb` → 6 位 `#rrggbb` 归一化后再传入 input
  - 元素 id 守卫：`#{(el.id ?? '').slice(-6)}`（防 `el.id` 缺失）
- `apps/web/src/store/editorStore.ts`：`loadProject` 用 `createElement` 默认值归一化每个加载元素，补齐缺失的 slider 字段（opacity/rotation 等），防御性兜底旧作品/模板。
- `apps/web/src/components/Canvas/EditorCanvas.tsx`：从 `common` 移除 `key: el.id`，改为在每个返回元素上直接传 `key={el.id}`（Text/Rect/Circle/Group×2/KonvaImage）。
- `apps/web/src/components/ErrorBoundary.tsx`（新增）：通用错误边界 class 组件，兜底 UI 含「重试 / 刷新页面」按钮，避免单组件崩溃致整页白屏。
- `apps/web/src/components/Editor/EditorApp.tsx`：用 `ErrorBoundary` 分别包裹 `EditorCanvas`（name="画布"）与 `PropertyPanel`（name="属性面板"）。
- `apps/web/index.html`：新增内联 SVG favicon（data URI），消除浏览器自动请求 `/favicon.ico` 产生的 404 控制台错误。

## 新问题：点击模板/新建任务提示「使用模板失败，请重试」

### 现象
- 用户反馈：localhost:5173 点击任意模板（或「新建作品」）均弹「使用模板失败，请重试」。

### 排查
- 后端 `/api/templates/{id}/use` 用全新 token 实测返回 201 + 完整 project/schema（端点本身正常）。
- 后端 JWT secret 为稳定值（`process.env.JWT_SECRET ?? 'h5design_jwt_secret_dev'`），重启不会使旧 token 失效。
- 根因：**access token TTL 仅 2h，且前端从不使用 refresh token**。
  - `apps/web/src/api/client.ts` 的 `request()` 遇 401 直接 `clearTokens()` 并抛错，无刷新重试。
  - `apps/web/src/store/authStore.ts`：`isAuthenticated: !!getStoredUser()` 仅看 `user_info` 是否存在，不校验 token 是否有效。
  - 结论：用户会话较长（跨后端 11:31 重启 + 2h 窗口），access token 已过期 → 每个需鉴权的请求（useTemplate/createProject）均 401 → 捕获后弹「使用模板失败」。Dashboard 的「新建」按钮文案为 `errors:dashboard.createFailed`，与模板文案不同，但同属 token 失效导致。

### 修复
- `apps/web/src/api/client.ts`：
  - 新增 `getRefreshToken()` / `refreshAccessToken()`（裸 fetch 调 `/api/auth/refresh`，成功则 `setTokens`+`setStoredUser`）。
  - `request()` 增加 `_retry` 内部参数：遇 401 先静默用 refresh token 换新 access token 并重试一次；刷新失败才清理整个会话（含 `user_info`）并抛错。
  - 因用户 refresh token（7d）仍有效，修复后其下次点击模板会自动刷新并成功，**无需手动重新登录**。

### 验证
- 前端 `tsc --noEmit`：0 errors ✅
- 后端链路实测（探针脚本）：用过期 access token 调 `/use`→401 → 用有效 refresh token 调 `/api/auth/refresh`→换新 token → 用新 token 重试 `/use`→201 SUCCESS ✅
- 临时探针脚本（probe-use.cjs / probe-refresh.cjs）已清理 ✅

### 🔴 关键 Bug 修复：全局 ValidationPipe 剥离请求体（影响整个后端）
- **现象**：P3-D 烟测发现 `PUT /api/projects/:id` 保存后版本数为 0；进一步诊断发现 `title` 被存为空字符串、`schema` 嵌套 `elements` 变为 0。
- **根因**：`apps/server/src/main.ts` 的全局 `ValidationPipe({ whitelist:true, transform:true })`。
  - `whitelist:true` 会**剥离所有没有 class-validator 装饰器的 DTO 属性**。项目 DTO（CreateProjectDto/UpdateProjectDto）的 `title`/`schema`/`snapshot` 等无装饰器 → 被整体丢弃。
  - `transform:true` 会让 class-transformer 把 `schema`（编辑器任意 JSON 工程数据，非 class）递归改造 → 嵌套 `elements` 等结构丢失。
  - 仅 `auth.dto.ts` 有装饰器（不受影响），项目/模板/发布等端点全部中招。
- **修复**：改为 `new ValidationPipe({ whitelist:false, transform:false })`。
  - 关掉 whitelist → 不再剥离任意属性；关掉 transform → 嵌套 `schema` JSON 原样透传。
  - 鉴权 DTO 自带装饰器，关掉 transform 后仍正常校验（校验不依赖 transform）。
- **影响范围**：此 Bug 在 P3-D 之前已存在，意味着此前所有作品保存都丢失了 `title`/`schema` 实际内容（发布页可能为空）。修复后全链路数据正确。
- 验证：修复后诊断脚本 `GET title="我的标题XYZ"`、`schema.elements=1`、`snapshot` 生效（版本数正常）✅。
