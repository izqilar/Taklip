## 续：用户反馈「编辑器字体列表看不到自定义字体」→ 根因是路由前缀（Task #27）

用户报告：服务端 `GET /fonts` 有 5 条数据，但 web/运营端编辑器字体下拉只有 6 个系统字体；`fonts.json` 仍是 `[]`（这是**正常的**——扫描走目录，清单只是可选元数据补充，不是入库来源）。

### 一、真根因（3 个，全部修掉）

1. **★ 字体控制器路由前缀与全局约定不一致**（这是直接根因）。
   `font.controller.ts` 写的是 `@Controller('fonts')`，而其它控制器都是 `@Controller('api/...')`。两端请求基址不同 → 两条路都错、且异常都被 `bootstrapFonts()` 的 catch 静默吞掉：
   - 运营端 `API_URL='http://localhost:3000/api'` + `/fonts` → `/api/fonts` → **404**
   - web `BASE_URL=''` + `/fonts` → **不在 vite proxy 列表**（只代理 `/api`、`/uploads`、`/public`）→ dev server 返回 `index.html` → `JSON.parse` 失败
   修复：控制器改 `@Controller(['api/fonts', 'fonts'])`（双前缀兼容旧脚本）；web `api.fonts()` 改 `/api/fonts`。
   **教训：界面「接口有数据但没内容」时先看 Network 面板的真实 URL 与状态码，别只看服务端 curl。**

2. **字体目录异步 vs 选择器同步渲染**：`getFontCatalog()` 同步读快照，目录异步拉取，回来后无 state 变化 → 不重渲染 → 永远只有系统字体。
   修复：core 新增 `subscribeFontCatalog(cb)`（`setFontCatalog` 时通知），`ComponentSettingsPanel` 用 `useSyncExternalStore` 订阅。

3. **`document.fonts.ready` 是一次性 Promise**：`SchemaRenderer.TextElementView` 原本只 `ready.then(bump)`；若字体在挂载**之后**才 FontFace 注册（发布页/导出页正是如此），早已 resolve → 不重排 → 字变了但字宽/换行不对。
   修复：额外订阅 `fonts` 的 `loadingdone` 持续事件（卸载时 removeEventListener）。

### 二、连带补齐：发布页此前完全没有字体注册
`packages/render` 全包无 `ensureFont`/`setFontCatalog` 调用 → 编辑器选了自定义字体，发布出去访客端静默回退系统字体。

## startup.ps1 优化（步骤 2.5「停止陈旧进程」消除红色 [ERR]/TerminatingError 噪声）

用户贴出 startup.ps1 运行日志：脚本最终成功（三端 200），但步骤 2.5「stop stale process(es) before Prisma generate」刷了一堆红色 `PS>TerminatingError(Stop-Process)` + `[ERR] could not stop PID X : 找不到进程标识符为 X 的进程`。

### 根因（两个）
1. **幻影 PID**：`Get-CimInstance Win32_Process -Filter "CommandLine LIKE '%server-watchdog.js%'"` 同时匹配了 `cmd /c start "" /min cmd /c "node scripts\server-watchdog.js ..."` 的 **`cmd.exe` 包装进程**（其命令行也含 `server-watchdog.js`），该包装进程 spawn 出 node 后立刻退出 → 被收进 `$stale`，稍后 Stop-Process 时早已不存在 → 报错。
2. **无存在性预检**：PID 在「枚举」与「Stop-Process」之间可能因竞态/被同循环更早一条 kill 连带回收而消失；而 `Stop-Process -ErrorAction Stop` 在 `$ErrorActionPreference='Stop'` 下会把缺失 PID 写成红色 `TerminatingError` 进 transcript。

### 改动（startup.ps1）
- watchdog 枚举加 `Name = 'node.exe' AND` 前缀，只匹配真正的 node 工作者，排除 cmd 包装幻影。
- stop 循环：先 `Get-Process -Id $lp -ErrorAction SilentlyContinue` 预检；不存在 → `Log "skip PID $lp (already exited)"`（不再 [ERR]）；存在才 `Stop-Process -ErrorAction SilentlyContinue` 并验证已死（仍活着→`[WARN]`）。
- Prisma EPERM 重试路径（原 `Stop-Process -ErrorAction Stop` 空 catch）同样加存在性预检 + `SilentlyContinue`，去掉 transcript 噪声。
- 语法校验 `Parser]::ParseFile` → `ERROR_COUNT=0 / SYNTAX_OK`。
- **未实跑整脚本**（会重启 :3000/:5173/:5174 干扰当前会话）；如需复验直接重跑 `startup.ps1` 观察 2.5 步骤应只剩 `[OK] stopped` 与 `skip ... already exited`，无 `[ERR]`。

## Task #28 — 缩放无损 / 矢量不锯齿（Task #19 的缩放实现升级）

### 需求
用户实测 Task #19 的缩放后反馈：「放大看到的是像素级内容，越放大约模糊，没有按矢量形式缩放」——要求文本/形状等矢量内容放大时重绘清晰、不失真，只有像素图片才应放大可见像素点。

### 根因（两个）
1. **★ 缩放用 CSS `transform: scale` 包裹 Konva 画布**：Konva 已把矢量光栅化成位图，CSS 再把整张位图整体位图放大 → 文本/形状呈像素化模糊。正确做法是把 scale 交给 Konva 内部（`Stage` 的 `scaleX/scaleY/x/y`），每帧按当前舞台像素尺寸把矢量**重新光栅化** → 任意倍率都清晰。
2. **`stageSize` 从未被更新**：重构时本应加的 `ResizeObserver`+`useLayoutEffect` 没落盘，`stageSize` 恒为 `{0,0}` → Konva 画布 0×0 不可见（编辑器虽加载完、但画布区域空白）。

- 移除画布父 div 的 CSS `transform: scale(zoom)`「缩放世界层」；`<Stage>` 直接收 `width={stageSize.w} height={stageSize.h} scaleX={zoom} scaleY={zoom} x={pan.x} y={pan.y}`（内部 scale=矢量无损重绘）。
- 新增 `useLayoutEffect` + `ResizeObserver` 监听 `viewportRef`，测量真实视口尺寸写入 `stageSize`（舞台铺满视口，缩放/平移由 Konva 内部承担）。
- `Ruler` 重写为「可见范围内」SVG 矢量刻度（屏幕坐标 `pan + c*zoom`，随 zoom/pan 计算），不再位图拉伸。
- DOM 覆盖层（文本编辑 textarea / 图集预览 `GalleryEditorOverlay`）保留 `transform: translate(pan) scale(zoom)` 同步映射（仅 DOM 覆盖，非画布），与画布像素对齐；缩放控制条/工具栏仍是视口级兄弟节点不缩放。
