### ① 图片边框三端不一致（渲染后变粗）— 已修复 `236b708`
- 根因：DOM 侧 `box-sizing:border-box` 把 `border:Npx` **全部画在元素盒内**（内容缩到 w-2N）；
  Konva 侧描边横跨元素边缘（约 N/2 在盒外）→ 预览/导出显得更粗。
- 修法：`EditorCanvas.tsx` + `KonvaElement.tsx`（两处必须同步）把图像内容裁到内容盒
  （`clipFunc + clipRoundedRect`，内圆角 = 外圆角 − borderWidth），边框改为居中画在内边缘的
  `Rect`（solid 一条；double 两条 `bw/6`、`bw-bw/6`，各 `strokeWidth=bw/3`）。
- 验证（1:1）：边框厚度 Konva 7.00 vs DOM 7.00，outer/inner 30~37、40~47、233~240 两端精确重合。

### ② 文本垂直位置在预览/导出偏低 — 已修复 `236b708`
- 根因：Konva 默认 `textBaseline='middle'`（锚在 em 盒中点），CSS `line-height` 居中内容盒，
  差 `(ascent+descent−unitsPerEm)/2`，随字号放大（38px ≈ 3.4px 下移）。
- 修法：`measureFontMetrics()` 新增 `middleToBaseline`（同串文本 'alphabetic'/'middle' 两次
  measureText 之差）；DOM 侧用 `0×0 inline-block` 探针实测真实基线；修正量加到**字形盒 top**。
- 关键坑：① 用 `transform` 施加修正会被 Chrome 合成层**像素吸附**成 ±1px 抖动 → 必须用 `top`；
  ② 修正加在字形 top 时测量值含上一轮修正，必须 `− textShift` 否则无界发散（曾写出反馈环）；
  ③ 用 `wrapRect.height / lineHeightPx` 自测真实缩放，不要信传入的 scale prop。
- 验证（1:1）：4 个文本元素重心 Δ ≤ 0.01 设计像素。

### ④ 镜像后调整大小错乱 — 已修复 `b66f66d`
- 根因 1（主因）：`Transformer.setNodes()` 单选时用 `node.getAbsoluteRotation()`，
  而它对 `scaleX=-1` 的节点会把镜像折叠成 **±180°** → Transformer 本地坐标系翻转 180°，
  **拖右边反而变窄**（右拖 +40 实测得 −40）。修法：`useSingleNodeRotation={false}` +
  绑定后显式 `tr.rotation(el.rotation)`。
- 根因 2：`decompose()` 的 `scaleX` 恒为正，镜像符号折叠进 `scaleY`(负)/`rotation`(±180)；
  旧 `toVisualRotation` 先复位再判定符号 = 死代码，且「仅水平镜像」分支推导本身错误
  （应还原 0 却给 180 → 自己变成垂直镜像）。改用矩阵反解 `unflipTransform`：
  `N = M·S(fx,fy) = delta·R(φ)`，`decompose(N)` 同时得缩放与真实视觉旋转。
- 根因 3：拖拽中每帧复位节点属性 → Transformer 下一帧算出反向修正 → 来回振荡。
  改为拖拽中**完全不改节点**，仅 `transformEnd` 一次性反解 + 复位 + `skewX(0)`。
- 根因 4：缩放不得改旋转（旋转对象非等比缩放时 Konva 写 skew，实测 30° 被写成 278.87°）→
  按 `Transformer._movingAnchorName === 'rotater'` 判定是否为旋转操作。
- 验证：`scripts/e2e_mirror_resize.mjs` 21/21（未镜像/水平/垂直/双向 × 横/纵/斜拖 + 30° 旋转回归），

## 渐变文字镂空缺陷修复（完成，SchemaRenderer.tsx）

### 根因
`background-clip:text` 的背景绘制区=**span 盒本身**（height=fontSize=1em）。CJK/粗体字形
ink（ascent+descent>1em）溢出 span 盒底部，溢出部分「有字形遮罩、无背景可画」→ 笔画下部
整块透明镂空（受控实验 grad48 模式缺失 19.47%，结构性）。

### 修法（packages/render/src/SchemaRenderer.tsx，仅 textPaintStyle 分支）
- 填充 span 加高至 `height: el.fontSize * 2`（top 不变 → 基线探针 firstFillRef 相对测量免疫），
  覆盖向下溢出的 ink；实测修复后实验缺失 0.007%。
- `backgroundPosition` 用 `Math.round()` 取整：Chromium 在 clip:text + 小数偏移下栅格化
  字形遮罩会出现 1 设备像素发丝裂缝。

## 文本框缩放「整体滑动」+ 渐变文字「顶部镂空」二次修复（完成，未提交）

用户反馈上一轮「橡皮筋修复」与「渐变镂空向下加高」两个都没解决，且缩放引入了新问题：拖边框时
文字+边框整体随鼠标滑动、框宽高不变（滑动）；渐变文字预览/导出顶部仍缺字。本轮重做。

### 问题一：整体滑动（根因 + 修法）
- 根因：上一版 `onTransform` 每帧把组 scale 复位为基准 `bsx/bsy` 并把尺寸写进子层，但随后
  用 `W = el.width * (node.scaleX()/bsx)` 折算宽高。Konva `Transformer._fitNodesInto` 每帧基于
  「节点当前绝对包围盒」算增量 delta 并累乘进节点自身变换，故 `node.scaleX()` 在复位后下一帧
  只是「相对当前子层尺寸」的**增量**（非累积）。于是一复位，累积尺度逐帧丢失 → 框长不到鼠标
  目标、整体随鼠标平移（滑动）。
- 修法（`EditorCanvas.tsx`，仅文本元素、非镜像、非 rotater）：
  - 新增 `tfSize` ref 维护累积尺寸。每帧读 Konva 刚写入的增量 `incX = node.scaleX()/bsx`，
    目标 `W = tfSize.w * incX`（prevW × 增量 = 绝对累积目标，不丢）；再把组 scale 复位为基准、
    把 W/H 写进所有子层（向中心平移 `base.x-dx` 保持居中），末了 `tfSize={W,H}`。
  - 数学证：下一帧 Konva 绝对盒=W、delta=目标/W → node.scaleX()=目标/W → W=prevW×目标/W=目标，
    精确累积；子层中心恒固定于 offset(=el.w/2,h/2)，故中心不漂移、不滑动。
  - `onTransformEnd`：文本走 `tfSize` 折算 kx/ky（绕开 unflip 的镜像折叠）；旋转/镜像走
    `unflipTransform`。**关键**：非「rotater」拖动的尺寸变更 `rotation` 必须用 `el.rotation`，
    不得用 decompose 值（非等比缩放会让 decompose 出 278.87° 而非 30°）；旋转手柄才用 decompose。
- 验证 `scripts/e2e_text_resize.mjs` 5/5：框 200→250（=鼠标目标，确为缩放非滑动）、文字绝对
  缩放比恒 1.000（无橡皮筋）、组缩放复位≈1。回归 `e2e_mirror_resize.mjs` 21/21（含 30° 旋转
  缩放保角）。

### 问题二：渐变文字顶部镂空（根因 + 修法）
- 根因：上一版只把填充 span 向下加高（`height:fontSize*2`, top 不变），覆盖**底部**溢出 ink；
  但部分字体 ink 从 em 盒**顶部**溢出（用户截图红框标在字形顶部）→ 顶部溢出仍无背景可画 → 镂空。
- 修法（`SchemaRenderer.tsx` fill span，textPaintStyle 分支）：改为**上下对称扩展 1em**——
  `boxSizing:border-box; top: glyphBase.top - fontSize; height: fontSize*3; paddingTop/Bottom: fontSize`。
  padding 把背景绘制区向外推 1em 而 `top` 上移同量，二者抵消使**字形内容位置不变**（基线探针
  firstFillRef 不受影响，三端垂直对齐不变）；背景绘制区因此覆盖顶部+底部溢出 ink。
