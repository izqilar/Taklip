## 文本轮廓 + 阴影：编辑器不渲染阴影 BUG
- 现象：文本不加轮廓时阴影在编辑/展示模式都可见；加轮廓后编辑器里阴影消失、发布页可见。
- 根因（查 konva@9.3.22 源码确认）：shadowForStrokeEnabled 默认 true，编辑器两处 Text 把 textShadow 写死 shadowForStrokeEnabled:false -> 阴影只追 fill（字形填充）。一旦文本有轮廓（stroke+fillAfterStrokeEnabled=true），带轮廓字形的可见边缘是描边而非填充，false 让阴影不追描边 -> 编辑器里轮廓文字无阴影；而 DOM 发布页 text-shadow 始终挂在 WebkitTextStroke 之上，故展示页有阴影。
- 修复：EditorCanvas.tsx 与 KonvaElement.tsx 的 textShadow 改为 shadowForStrokeEnabled: hasTextOutline（有轮廓=true 追描边、无轮廓=false 追 fill），与 DOM 一致。注：两文件 textShadow 曾出现重复声明，已删旧留新。

## 分散对齐 kashida 撑出边界框 BUG（Konva 画布）

- 现象：编辑器对文本做「分散对齐 / justify-all」时，文本内容超出边界框——具体是**左端**越过边界（常规从左到右对齐无问题）。强制分散对齐时会在相连字母间插延长符(Tatweel)铺满，但要限定单词两端不越界。
- 根因（定量实锤）：`core/text.ts` 的 `kashidaForJustify` 按 `0.22em` 估算单 Tatweel 推进宽（32px 下 = 7.04px），但实际字体（如 ALKATIP-Kufi）实测单 Tatweel = 8.19px（部分连写对达 11.3px）→ 低估约 16% → 计算插入数量过多 → 行宽超出内容框。而 `konvaShared.tsx justifySceneFunc` 对 RTL 行设 `textAlign:'right'`、`_partialTextX = contentWidth`（以行盒**右缘**为书写锚点），多出的宽度全部从**左端**溢出 → 正是用户看到的越界。旧算法实测行宽 325px vs 内容框 260px，左溢 ~65px。
- DOM 发布/导出页走原生 CSS `text-align:justify`，浏览器原生插 kashida 且约束在框内 → 无此 bug；**仅 Konva 画布受影响**。

- **裁剪按钮接真功能**：原 `onClick={() => alert(cropTip)}`（"裁剪功能即将上线"）→ 改为打开裁剪对话框。
