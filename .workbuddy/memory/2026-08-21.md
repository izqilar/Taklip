## 图片裁剪两处 bug 修复
- **(1) 移动破坏裁剪尺寸**：根因在 `ImageCropDialog.tsx` 的 `normalizeCrop`，原实现 `width = clamp(crop.width, 0.01, 1 - x)` 把宽高与位置耦合——靠近右/下边界移动时 `x/y` 增大导致 `1-x` 变小，width/height 被钳小。修复为「先独立钳宽高 `[0.01,1]`，再钳位置 `x∈[0,1-width]`、`y∈[0,1-height]`」，移动时尺寸保持不变、仅位置受边界约束。逻辑单测验证（移动 right 0.3 / 左下移均保持 0.5×0.5）。
- **(2) 比例标签与效果**：`standard` 选项标签由 i18n「标准屏」改为字面「9:16」（值仍为 9/16）；`fullscreen` 由「全面屏」改为「16:9」且值由 `9/19.5` 改为 `16/9`（实际裁剪效果随之变横向）。移除 `editor.json` 中已弃用的 `cropRatioStandard`/`cropRatioFullscreen` 两个 i18n key（zh-CN/en）。`fitCropToRatio(16/9)` 现生成横向裁切框（width 1 > height 0.5625）。

## 预览裁剪 + 视频空白修复（#287/#288/#289）
- **预览裁剪不渲染根因**：原 `DOMRenderer` 图片裁剪基于存储的 `imgEl.naturalWidth/Height` 做归一化换算，若该字段未落库会与真实像素不一致，裁剪显示错位。
  - 修复：把 image case 抽取为 `ImageElementView` 组件（`DOMRenderer.tsx`），用 `useState` 记录 `onLoad` 拿到的**真实** `naturalWidth/Height`，裁剪换算基于真实像素，所见即所得。`data-has-animation` 仍挂在 wrapper 上，动画链路不受影响。
- **视频导出一片空白根因**：`exportVideo.ts` 用 `html-to-image.toCanvas` 对离屏 `DOMRenderer` 截图；以图片为主的作品在离屏环境里 `html-to-image` 远程拉取并内嵌图片易失败/竞态，导致所有图片丢失 → 整屏空白。

## 修复：导出视频「白屏」根因 + 渲染对象动画时间线（#290 收尾）
- 现象：点「导出视频」能生成 mp4，但画面全白，设计元素/动画/页面切换都没渲染。
- **白屏真正根因**：`html-to-image` 的 `toCanvas` 把被截节点克隆后**直接**塞进 SVG `<foreignObject>`（viewBox `0 0 width height`，无坐标补偿）；而旧代码把截图 `host` 写成 `position:fixed; left:-10000px`——该 inline 样式被原样复制进克隆体，导致整页内容被推到 -10000px、完全落在 0..width 的 viewBox 之外 → 截出纯白画布。（early 的「img CORS 导致空白」假设只是次要因素，此偏移才是主因。）
- 修复（`apps/web/src/utils/exportVideo.ts`）：离屏定位交给**外层 wrapper**（`left:-10000px`），被截 `host` 自身固定在 `position:absolute; left:0; top:0`，其克隆体即落在 (0,0)，内容正确呈现。
- **动画时间线**：旧管线只截每页「设计终态」静态帧再做跨页淡入，对象动画完全没回放。重写为逐页挂载 `DOMRenderer(animated:true)`，让每个元素的入场/强调/循环动画在 DOM 上真正播放（与编辑器、预览态同一条 GSAP 链路），按 `CAPTURE_FPS=20` 节拍把「当前动画态」截成 canvas 帧绘到录制画布；页面间交叉淡入（先截下一页静止帧叠加混合，再挂载下一页让其对象动画接着播放），形成第一页→最后一页的连贯时间线。
  - 图片预加载改为直接 `cloneAndInline` 写回作品副本（src/poster/backgroundImage 全替换 dataURL），渲染即命中本地数据，避免 React 重渲染把已内联的 dataURL 还原成远程 URL、也避免 html-to-image 二次远程拉取。
  - 单帧 `toCanvas` 失败回退纯白帧；`withTimeout` 兜底单帧(20s)/录制收尾(15s) 仍存在，避免卡死。
  - 删除了旧 `renderPageToCanvas`/`playFrames`/`inlineImages`/`urlToDataURL`(仅预加载用)；`preloadImages/collectImageUrls/pickMimeType/makeBlankCanvas/withTimeout/delay` 保留。

## 修复：视频导出对象动画被截断/跳帧 + 表格空白（Konva 离屏管线）
- 现象：高清 mp4 能导出，但每页对象的对象动画「缩水/不完全播放/跳帧」，且表格对象内容不渲染。
- **动画截断根因**：`konvaVideoExport.ts` 的 `pageAnimsDuration` 只取单条 `delay+duration` 上限，而 `playAnimationsOnNode` 串行播整组（入场+强调）动画、且多段动画（bounce/shake/swing/headShake…）内部还有多段，真实结束远晚于该值；主循环又用 `performance.now()` 墙钟 + `delay(1000/FPS)` 截帧，而 Konva.Tween 靠 rAF 推进，二者脱节 → 长序列动画被截尾、跳帧。
- **表格空白根因**：`table` 是 `widget` 的 `kind:'table'`，`KonvaElement` 的 `case 'widget'` 只委托通用 `CanvasWidget`（仅画标题框不画内容）；真实内容在 `widgetModules.tsx` 的 `TableDOM`（读 `el.data.csv`）。导出走 Konva 渲染 → 表格只显示空框。
- 修复：
  - **新增 `apps/web/src/animations/konvaTimeline.ts`**（可 seek 的 GSAP 时间线引擎）：每个对象的整组动画建成一条 `paused` 的 GSAP 时间线，直接驱动 Konva 节点的 x/y/scale/rotation/opacity/skew/offset（proxy 模式）；`tl.totalDuration()` 给出精确总时长，导出主循环按帧索引 `seek(t)` + `stage.toCanvas` 逐帧截帧，与 `captureStream(30)` 节拍严格对齐，杜绝截断/跳帧。`computeStates`/`findAnimationDef` 复用（前者在 `konvaPlayer.ts` 改为 `export`）；多段时间线动画段数据逐段镜像 `konvaPlayer` 的 `play*` 系列，`swing`/`headShake` 用 `tl.set` 瞬时切换旋转轴（offset/position）再只播 rotation/scale，与编辑器预览完全一致。已用独立 gsap 脚本实测 `seek` 在暂停时间线上能正确应用 set/to 并 clamp 超界。
  - **`KonvaElement.tsx`**：`case 'widget'` 对 `widget==='table'` 改派发新增 `KonvaTable`；`apps/web/src/elements/widget/KonvaTable.tsx`（NEW）用 Konva Rect/Text 真绘制表头（themeColor 底白字）+ 单元格（边框、奇偶行底、居中、clip 防溢出），CSV 解析逻辑（按 `\n` 分行、`,` 分列）与 `TableDOM` 等价 → 所见即所得。
  - **`konvaVideoExport.ts`**：移除 `pageAnimsDuration`/`playPageAnimations`/`getAnimationConfigs`，主循环改为「`buildPageTimelines(stage,page)` → 逐帧 `seekPageTimelines(timelines, f/FPS)` → `captureFrame` → `delay(1000/FPS)`」，`totalFrames = ceil((timelines.total + HOLD) * FPS)`；跨页仍交叉淡入到下一页 t=0 首帧。
