## 架构收口：编辑器内核 CSS 自包含（web/admin 像素一致）

### 用户诉求
"web 端编辑器界面的视觉效果和运营端差异较大。能否把编辑器内核+CSS 布局独立于 web 端和运营端，当调用的时候做到 web 和运营端完全一致的视觉表现力？"

### 根因（此前两端表现力不一致的来源）
- admin 为兼容 antd 关闭全局 `preflight`（`corePlugins.preflight=false`），而 web 开启 → 同一份内核 Tailwind 类在两端的"基础重置"环境不同。
- admin 被 antd 全局样式污染（按钮/标题/图片默认样式），web 无。
- 两端 `tailwind.config.js` 各自扫描内核包、各自编译 → brand 色不一致（admin `#C24B2E` vs web `#FF4D6D`）、corner case 类编译结果不同 → 表现力漂移。

### 解决方案（内核自包含 CSS，单一事实源）
1. **内核自建 CSS 产物**：`packages/editor/tailwind.config.js`（扫描 `./src`+`../render/src`，`brand=#FF4D6D` 对齐 web，`corePlugins.preflight=false`）+ `packages/editor/src/styles/editor.css` → `build:css` 脚本（`tailwindcss -i ... -o ./dist/editor.css --minify -c ./tailwind.config.js`）产出 `dist/editor.css`。`package.json` 用 `exports["./styles.css"]:"./dist/editor.css"` 暴露。
2. **两端移除内核包扫描**：`apps/web/tailwind.config.js` 与 `apps/admin/tailwind.config.js` 的 `content` 均删掉 `../../packages/editor/src/**` 与 `../../packages/render/src/**`（杜绝双编译/漂移）。
3. **两端统一 import**：`apps/web/src/main.tsx` 与 `apps/admin/src/main.tsx` 均在各自 `index.css`/tailwind.css 之后 `import '@h5design/editor/styles.css';`。
4. **作用域锚点进内核（关键）**：`packages/editor/src/styles/editor.css` 顶部一段作用域限 `.editor-canvas-wrap` 子树的局部 preflight（box-sizing:border-box、border 默认 solid+`#e5e7eb`、button/img/svg/input 去默认、统一 `font-family:system-ui…`、color `#1f2937`）；`packages/editor/src/components/Editor/EditorApp.tsx` 根 div 加 `editor-canvas-wrap` 类（**单一真值**，web/admin 共用一份，此前 web 缺失该 class 导致 preflight 未生效）。
5. **admin 去冗余**：`apps/admin/src/styles/tailwind.css` 删除原局部 preflight 块（现由包 editor.css 提供），仅保留 `.editor-canvas-wrap > div {width/height:100% !important}` + `.editor-topbar` 布局覆盖。
6. **启动编排**：`startup.ps1` 第 4.5 步 `pnpm --filter @h5design/editor build:css`（SKIP_EDITOR_CSS=1 可跳过）。

### ⚠ 关键坑：editor.css 内 CSS 顺序
`.editor-canvas-wrap` 作用域 preflight 块**必须写在 `@tailwind utilities` 之前**。两者同特异性 (0,1,0)，后声明胜——若 utilities 在前，`.border{border-width:1px}` 被 preflight 的 `border-width:0` 覆盖 → 边框全消失（admin 实测 `borderVisible:false`）。修正后 admin `borderCount:23` / border 色 `rgb(229,231,235)` 正常。

## 发布页「原样展示」修复（PublishedH5 自适应缩放）

### 用户诉求
"web端和运营端展示请柬首页渲染有缺陷，没有按照作品设计原稿(编辑器的效果)首页的视觉效果展示。请仔细检查并优化原样展示视觉效果"

### 根因
`PublishedH5`（render 包，被 web PublishedPage 消费）渲染 375×667 设计稿时**不做任何缩放**：
- **桌面端**：375px 内容放入 `max-w-md`(448px) 卡片 → 左对齐，右侧 ~73px 空白条（空 strip）。
- **窄屏手机（<375px）**：卡片 `w-full`=360 但内容仍 375 → `overflow-hidden` 裁切掉右侧 15px。
- 运营端的"查看发布"链接打开的是同一个 `/p/:code`（web 页面），所以**两端共享同一缺陷**。

### 架构背景（关键纠正）
- 编辑器**实时画布 = Konva (Canvas 2D)**，不是 render 包。
- render 包（DOM/CSS）只用于：① 编辑器预览弹窗 PreviewModal；② web 已发布页 PublishedPage；③ admin 所有缩略图 SchemaThumbnail。
- 所以"编辑器效果 vs 发布页"本质是 **Konva ↔ DOM 两套渲染后端**的差异。本次修复解决的是 DOM 路径内的**布局/缩放缺陷**（最明显的视觉缺陷）。

### 修复（packages/render/src/SchemaRenderer.tsx — PublishedH5）
1. 新增 `containerRef` + `ResizeObserver`：测量父容器宽度，计算 `scale = containerWidth / project.width`。
2. 渲染结构改为三层：
   - 外层 `<div ref={containerRef} data-published-h5="" style={{width:'100%'}}>` — 测量锚点。
   - 中层 `<div className="relative" style={{width: width*scale, height: height*scale, overflow:'hidden'}}>` — 按缩放尺寸预留布局空间 + 裁剪 transform 不改变布局占位带来的溢出。
   - 内层 `<div style={{position:absolute, top:0, left:0, width, height, transform:`scale(${scale})`, transformOrigin:'top left'}}>` — 绝对定位 + transform 缩放的舞台（与 SchemaThumbnail 同策略）。
3. MusicPlayer（absolute right-3 top-3）和多页分页点（absolute bottom-4 center）放在中层 relative 容器内 → 锚定到缩放后的页面边界。
4. 单页和多页两个 return 分支均已改造。

### CSS 技术要点
- `transform: scale()` **不改变元素布局占位**（unscaled 375×667 footprint persists），所以必须用 absolute+overflow:hidden 裁剪——否则 body 被 unscaled stage 撑开，回到原来的空 strip/裁切问题。
- 缩放策略与 `SchemaThumbnail` 完全一致（单一真值），保证 admin 缩略图和 web 发布页的缩放行为统一。

## 修复：编辑器保存后缩略图/预览不刷新 + 背景图丢失（23:55）

- 背景色（CSS 颜值）不经过此变换 → **保留**

### 修复

| 文件 | 改动 |
|---|---|
| `apps/server/src/project/project.service.ts` | `findAll()` 增加 `draftSchema` select，返回前做 `draftSchema ?? schema` 映射（与 `findOne` 一致） |
| `packages/core/src/sanitize.ts` | `sanitizePage()` 中 backgroundImage 只提取+校验裸 URL，不再包 `url()`；兼容已存储的 `url(...)` 格式（自动解包） |
