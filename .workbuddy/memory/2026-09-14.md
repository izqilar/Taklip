## 修复：编辑器与渲染器视觉一致性（双重 bug）

### Bug 1: 运营端模板/作品卡片预览空白
**根因**: `provider-console.controller.ts` 的 `catalog()` 和 `user-console.controller.ts` 的 `works()` 只 select 了 `schema`（live），没有 `draftSchema`。对于已编辑但未发布的作品（内容仅在 draftSchema 中），列表返回空 schema → 缩略图空白。
**典型案例**: "学术交流邀请函"——schema 有 0 个元素，draftSchema 有 4 个元素（含"学术交流会"文本+照片）。
**修复**: 两个接口都增加 `draftSchema: true` 到 select，返回时合并 `schema: draftSchema ?? schema`。
**文件**: `apps/server/src/console/provider-console.controller.ts`, `apps/server/src/console/user-console.controller.ts`

### Bug 2: 文本在 DOM 渲染器中异常换行
**根因**: `SchemaRenderer.tsx` 文本元素使用 `whiteSpace: 'pre-wrap'`，CSS 会在容器宽度不足时自动折行；而 Konva Canvas 默认不折行。导致边界宽度的文本（如"结婚是光荣的"）在编辑器一行显示，在页面展示中换成两行。
**修复**: 改为 `whiteSpace: 'pre'`——保留显式换行（`\n`），但禁止 CSS 自动折行，与 Konva 行为对齐。
**文件**: `packages/render/src/SchemaRenderer.tsx` 第 403 行

## 修复：startup.ps1 启动闪退（PowerShell 解析错误）

### 现象
用户报告改完上一轮后 `startup.ps1` 一启动就闪退。

### 根因
`startup.ps1` 第 4.5 步（editor CSS 构建）的 3 行注释是**中文 UTF-8**，而文件头注释明确约定
"written in pure ASCII so it parses correctly under any codepage"。系统默认 `powershell.exe`(5.1)
读取无 BOM 的 .ps1 时用系统 ANSI 代码页（中文 Windows=GBK）解读，把 UTF-8 中文字节误读为乱码，
导致解析器在后续 `} else {` 处报"意外的标记 }"而崩溃。startup.log 的"上次成功"是 pwsh 7(默认
UTF-8) 或中文注释被加入之前跑的，文件本身无 BOM 才是症结。

### 修复
用 Python 把那 3 行中文注释替换为 ASCII 英文（恢复文件"纯 ASCII"约定，PowerShell 5.1 和 pwsh 7
都能解析）。验证：`[System.Management.Automation.Language.Parser]::ParseFile` 报 NO PARSE ERRORS；
实跑 startup.ps1（SKIP_DOCKER/INSTALL/MIGRATE/GENERATE=1）三个端口 3000/5173/5174 均 200。

### 铁律
**本仓库任何 .ps1 / .sh 启动/构建脚本保持纯 ASCII（英文注释）**，不要在其中写中文注释——
PowerShell 5.1 对非 BOM 的 UTF-8 中文会按 GBK 误读导致解析崩溃。需要中文说明就放 README 或代码注释。

## 修复：运营端弹出菜单内边距丢失（Task #15 — CSS 特异性冲突）

### 问题（用户第 4 轮反馈，2 张截图）
Task #14 统一 JIT 后，admin 端「形状」和「多媒体」弹出菜单的子项（矩形/线条/箭头…、图片/音乐/视频）
仍紧贴菜单左边界（无左内边距），且视觉上感觉"菜单过宽"。web 端同代码正常。

### 根因（CSS 特异性冲突）
`apps/admin/src/styles/tailwind.css` 中 scoped 按钮重置规则：
```css
.editor-canvas-wrap button:not(.ant-btn) { padding: 0; }
```
特异性 = **0-2-1**（class + element + `:not()` 伪类），高于 Tailwind 工具类 `.px-4` 的 **0-1-0**。
导致菜单项 `<button className="... px-4 py-2.5 ...">` 的水平内边距被 `padding: 0` 覆盖。

web 端正常是因为其 preflight 用 `button { padding: 0 }`（特异性 0-1-0），与工具类平级，
后声明的工具类胜出。admin 的 `:not(.ant-btn)` 增加了特异性，反而破坏了工具类。

### 修复
从按钮重置规则中移除 `padding: 0`，添加注释说明布局属性由 Tailwind 工具类控制。
文件：`apps/admin/src/styles/tailwind.css` 第 40~50 行。

### 验证

- 无需重启服务、无需 typecheck（纯 CSS 改动）
