## 三、下一轮目标：代理商工作台业务 / 菜单 / 页面标准化设计与优化

### 范围与定位
- **代理商 = AGENT 角色**；工作台位于运营端（apps/admin :5174）**AGENT 视角**。
- **视角铁律（P0，见 MEMORY.md §0）**：AGENT 登录后 `view === 'agent' === 自身角色 === 自身工作台`，**必须直接展示自身数据、绝不强制选 subject**。ADMIN 视察 AGENT 才经 `?subject=`（带辖区校验）。
- 相关已落地机制：组织内岗位体系（`agent/roles` 入口、`provider/team` 资源名）、侧栏角标（`BadgeKey` in resources.tsx + `useBadges`）、统一登录落点（AGENT→admin dashboard）。

### 建议开场步骤（下一轮先做，不要直接改代码）
1. **盘点现状**：列出 AGENT 视角当前所有菜单项（resources.tsx 中 `view==='agent'` 的资源）、各自 group 归属、路由、组件文件、Modal vs 整页形态。
2. **对照原型**：以 `UI_Design/index.html` 静态原型 + `docs/` 还原开发文档为唯一真值，列出与「标准化预期」的差距清单（菜单分组/命名/顺序/i18n 完整性/页面形态）。
3. **确认标准化目标**：与用户对齐菜单树最终结构、命名规范、i18n 覆盖、Modal→整页迁移范围（可复用 `admin-modal-to-page-migration` 范式）。
4. **分步实施 + 验证**：每改一批即三端 typecheck + Playwright 走查（见下方铁律）。

### 可复用技能 / 范式
- `console-agent-module`：代理商管理类列表「查看/编辑」浮动弹窗、行操作顺序与命名、编辑弹窗补字段 + Playwright 验证。
- `admin-modal-to-page-migration`：Modal 详情/设置页 → 整页路由 SettingPage 的范式与验收。
- `console-view-restore`：某一视角全量原型还原（菜单树重建）。
- `unified-login-routing`：角色落点调整。

### 已知坑（下一轮直接规避，详细见 MEMORY.md §5/§12 与今日日志）
- **i18n 行尾符**：admin `common.json`=LF、`web-common.json`=CRLF；脚本级注入必须检测 dominant EOL 按原格式写回，web-common.json 用「括号匹配 + 末尾成员后文本级插入」，勿整份 json.dump。
- **i18n 扁平点号键**：admin `common.json` 的 `pages.*` 下勿造扁平点号键（会被同名嵌套对象遮蔽）；新增文案写嵌套结构。
- **Playwright（运营端）**：①`layer.view` 不能用 localStorage 注入（identity 校正回自身）→ 点顶栏视角按钮；②objectScope 仅存内存（scopesByView），`page.goto()` 会清空 → SPA 内点侧栏导航；③AutoComplete 的 input class=`ant-select-selection-search-input` 且 placeholder 不透传 → 用 `[data-testid="objscope-search"] input`；④多 dropdown portal 共存时点 `.ant-select-dropdown:not(.ant-select-dropdown-hidden)` 的 `.last()`。
- **JSX 注释**：不能写在属性列表中间（`<Comp {/*..*/} prop />` 语法错误 → vite 崩白屏）。
- **同文件并行 Edit 互相覆盖**：必须串行 + Grep/Read 抽查落盘。
