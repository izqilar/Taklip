## 运营端四层菜单架构规划与落地（P1/P2 + 占位页）

### 背景讨论（上午）
用户提出运营端应按「管理总台 / 代理商中心 / 服务商中心 / 用户中心」四层重构。经多轮澄清定稿：
- 同一运营端 + 角色视图（沿用现有 Refine + RBAC/ABAC），不拆独立站点。
- **用户中心放 web 端**，运营端仅保留「用户管理」监督入口（视察/监督 app 全部用户状态行为）。
- 新增「评价与反馈中心」模块：投诉/好评/建议/咨询统一入口，层级升级流（用户↔服务商纠纷 → 代理商协商 → 升级总台仲裁）。命名经对比后用户拍板用**「评价与反馈中心」**（否决"工单中心/服务中心/服务评价中心"，认为"工单"概念模糊）。
- 新增「消息中心」模块：分层发布，总台可全局/区域+权威公告；代理商仅本辖区（权威公告需总台审核）；服务商仅一般消息；用户仅向相关服务商发一般/诉求。权威消息审核流是关键约束。

### P3/P4 落地（2026-08-26 下午，已执行并验证）
- **服务端 `ticket` 模块** `apps/server/src/ticket/**`（controller/service/dto/module）：
  - Prisma 新增 `Ticket` 模型 + `TicketType`(COMPLAINT/PRAISE/SUGGESTION/CONSULT/APPEAL)/`TicketStatus`(OPEN/NEGOTIATING/ESCALATED/ARBITRATING/CLOSED) 枚举；reporter/target/assignee 三方关系回向挂在 User 模型。
  - 作用域：`list` 按 role 注入 where（ADMIN 全量 / AGENT regionPath 前缀+本人认领 / SP 被诉+本人 / USER 本人）；`escalate`(AGENT→ADMIN)、`assign`(AGENT 认领)、`resolve`(ADMIN 关闭) 均做角色校验。
  - 路由 `api/tickets`（POST/GET/:id/GET?type&status&escalated/PATCH :id/assign|escalate|resolve），仅 AuthGuard('jwt')，角色约束在 service 内。
- **服务端 `message` 模块** `apps/server/src/message/**`：
  - Prisma 新增 `Message` 模型 + `MessageType`(ANNOUNCEMENT/NOTICE/APPEAL)/`MessageScope`(GLOBAL/REGION/OWN)/`MessageStatus`(DRAFT/PENDING/PUBLISHED/REJECTED)。
  - `create` 角色约束：ADMIN 可 ANNOUNCEMENT/NOTICE（GLOBAL/REGION）；AGENT 可 ANNOUNCEMENT(→PENDING 待审)/NOTICE（强制辖区 REGION）；SP 仅 NOTICE（OWN 指定角色）；USER 后台拒绝。
  - `inbox` 按 scope 过滤（GLOBAL 全可见/REGION regionPath 前缀/OWN targetRole 匹配）；`audit`(ADMIN) 列 PENDING；`approve`/`reject`(ADMIN) 审核流。
  - 路由 `api/messages`（POST/GET inbox/GET audit/PATCH :id/approve|reject）。
- **getAccess 权限串** `auth.service.ts`：ADMIN 补 feedback:read/review、message:read/audit/manage；AGENT 补 feedback:read/agent、message:read/agent/manage；SP 补 feedback:read/own、message:read/own。
- **运营端真实页面** `apps/admin/src/pages/feedback.tsx` 与 `messages.tsx`：从占位重写为角色感知页（读 `getStoredUser()` 的 role），feedback 含类型/状态筛选、 drawer 发起、AGENT「升级转总台/认领」、ADMIN「仲裁关闭」；messages 含收件箱/发布管理（按角色收敛 type/scope 选项）/ADMIN 权威公告审核（approve/reject）。用 `useLocation` 默认切到 `/escalated`、`/audit` 子路由对应 Tab。
- **验证**：`prisma generate` + `db push` 同步新表（注意：Prisma 引擎 DLL 被运行中的服务端进程占用导致重命名 EPERM，须先 kill 服务端再 generate）；`nest build`(system node)；服务端:3000 重启健康 200；curl 验证：ADMIN 建工单/列、AGENT 发 ANNOUNCEMENT→PENDING→ADMIN 审核→PUBLISHED、SP 发 NOTICE(OWN USER) 成功且 ANNOUNCEMENT 被 400 拒绝、SP inbox 仅见 targetRole=自身 的消息；admin typecheck + server typecheck 均 EXIT=0；5174 重启在线。

### 关键约束（防复发）
- Refine 菜单分组用 `meta.parent` 指向父资源 `name`；父项无 `list` 仅作分组头。
- 未映射资源 `permFor` 返回 null = 默认可见；四层分组可见性用 `canSeeByRole` 角色判定，不依赖服务端 permissions 数组完整性（数据权限仍由服务端 JWT 保证）。
- 未实现功能一律占位，禁止伪造数据。
