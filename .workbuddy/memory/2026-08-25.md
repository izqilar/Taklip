## 2026-08-25 晚（续2）：代理商改辖区保存 "Failed to fetch" 修复
- **现象**：`/admin/agents/edit/test_agent_x` 选辖区点保存抛 "Failed to fetch"（浏览器 fetch 网络层错误，非 HTTP 错误）。
- **根因（两层）**：
  1. **CORS 方法大小写**：`agents.tsx` 调 `dataProvider.custom({ method: 'patch' })` 用小写。fetch 规范只把 GET/HEAD/POST/PUT/DELETE/OPTIONS 自动规范为大写，`patch` 原样发出；浏览器 CORS 方法比对**大小写敏感**，服务端允许 `PATCH` 但请求是 `patch` → 预检/比对失败 → 抛 "Failed to fetch"。（`get`/`post` 小写没事，因为它们在 6 个安全方法内会被自动大写，唯独 `patch` 中招。）
  2. **Region id vs code 契约错配**：`Region` 模型 `id` 是 cuid，`regionPath` 才是国标 code 链；但 `RegionCascader` 级联 `value/onChange` 吐出 `n.code`（6位码），服务端 `updateAgentRegion`/`createAgent` 却用 `getById(dto.regionId)` 按 **cuid id** 查 → 查不到 → 400 "所选区域不存在"。同时编辑页回填 `findPath(tree, agent.regionId)` 拿 cuid 比对 `n.code` → 永不匹配 → 选区不回显。
- **修复**：
  - `dataProvider.custom` 内 `method: (method ?? 'GET').toUpperCase()`（单点根治，所有调用方小写 method 都能正确发大写，满足 Refine `custom` 字面量类型）。
  - `agents.tsx:92` 保持 `method: 'patch'`（由 dataProvider 统一转大写）。
  - `RegionCascader`：`toOptions` 改 `value: n.id`；`findPath` 改按 `n.id` 匹配（参数 `code`→`id`，含递归调用），emit/回填均用 cuid id，与服务端 `User.regionId`/`getById` 一致。
- **验证**：`apps/admin` `tsc --noEmit` EXIT=0；node 实测 `GET /api/regions/tree` 取到区级 `东城区 id=cmt834ads00jwzc24e2wlil78 code=110101`；`GET /api/admin/agents/test_agent_x` 确认 `role=AGENT`；用该 cuid id 发大写 `PATCH /api/admin/agents/test_agent_x/region` → **200 OK**（证明 code/id 契约已对齐）；CORS 预检 `OPTIONS`→204 且 `Access-Control-Allow-Methods` 含 `PATCH`。重启 运营端(5174) 在线。
- **启示（防复发）**：① 凡自定义 dataProvider 的写操作必须保证发出的 HTTP method 大写；② Region/行政区划类选择器 value 必须与服务端查找键（此处是 cuid id）一致，display label 用 name、path 用 id。
