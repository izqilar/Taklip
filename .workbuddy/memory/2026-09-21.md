## 平台角色边界规范化 — 需求讨论 + 方案设计（阶段 A：出文档，待评审）

### 需求
三个组织层（总台 ADMIN / 代理商 AGENT / 服务商 SERVICE_PROVIDER）将来都要调度内部员工，需要**组织内岗位（StaffRole）**划清业务处理边界。触发点是服务商「我的团队」的「团队角色」是自由文本 Input，没有权限含义。用户要求：先详细规划任务 + 出 `docs/平台角色边界规范化.md`，**审阅通过后才动代码**。

### 现状盘点（代码事实，勘查核实）
- `ProviderTeamMember`（schema.prisma:620-637）与 `User` **无任何关联字段** → 员工不能登录，岗位只是通讯录标签
- `teamRole` 自由文本 Input（providerDetailPages.tsx:268）；`funcPerms`/`dataScope` 只落库、**服务端零消费**（provider-console.controller.ts:989-990）
- team 接口无 DTO（`@Body() body: any`）、**无 PATCH**（:960-1004）
- 代理商 / 总台**完全没有**内部员工模块（agent/users、admin/users 管的是辖区内对象，非本单位员工）
- 权限串漂移成 3 份：`auth.service.getAccess`(在线源) / `auth.service.permLabelMap`(中文标签) / `admin.service.getPermissions`(**零调用死代码**)；前端 `accessControlProvider.permFor` 又是**另一套 key**，不读 permGroups
- `PermCheckGroup` 已实现但**零调用方**；`roles.tsx` 是纯前端常量只读视图
- `DataScopeInterceptor` 产出的是 `Prisma.UserWhereInput`，不是 ALL/REGION/SELF 枚举
- `jwt.strategy.ts:12-52` **未校验 `status===DISABLED`**

### 三个关键冲突（本轮必须处理）
1. **原型「婚庆策划」vs 代码「婚礼策划」**：`SVC_OPTIONS` 15 项中仅 **5 项**命中原型 `TEAM_SVC_META`（UI_Design/index.html:4691），**10 项需 fallback**；「婚礼策划」要加别名映射
2. **种子数据存量是自由文本**（seed-provider-view.js）→ 岗位控件必须 **AutoComplete**（可选可自填），不能用严格 Select，否则旧值显示为空
3. **员工权限不能取「∩ 雇主权限串」**：SP 在 getAccess() 只有 4 项（feedback/message），不含 order:* → 交集**恒为空**。P0 只声明不门控；P1 改「雇主可用权限域白名单」推导

### 方案（已写入文档）
- **双轴模型**：平台身份 `User.role`（不动）× 组织内岗位；生效权限 = 岗位功能权限 ∩ 雇主可用权限域 ∩ 数据范围
- **一表统三层**：新增 `OrgStaff{orgType,orgId,memberNo,name,phone,accountStatus,serviceType?,staffRole,duties,funcPerms,dataScope,personality}`，`@@index([orgType,orgId])`；存量 `ProviderTeamMember` 一次性导入，旧表**保留不删**（P2 再清理），对外 `/api/provider/team` 契约不变
- **不给员工新增平台角色**（沿用 USER），避免冲击 ROLE_HOME/canSeeByRole/getAccess/RolesGuard/DataScopeInterceptor
- **不复用 subject 机制**（它是 ADMIN 视察他人且客户端可信；员工是自登录）
- 三层岗位池：PROVIDER 按 serviceType 联动（原型 6 项 + 通用「店长/调度、财务专员」+ fallback）；AGENT 区域经理/入驻审核员/商务拓展/财务/客服；CONSOLE 超级管理员/内容运营/审核员/财务/客服
- 数据范围按层白名单：PROVIDER(self/service/provider) · AGENT(self/region/agent) · CONSOLE(self/all)；沿用 DB 现有 lowercase 值，不新造枚举
- 权限子集：服务商 8 项对齐原型 `TEAM_FUNCS` → `order:view/order:handle/order:aftersale/message:send/template:publish/content:offline/data:export/qualification:manage`
- **红线 6 条**：R-01 继承裁剪 / R-02 财务发起审批分离 / R-03 防自我提权 / R-04 执行岗隔离+maskPhone / R-05 离职停用+留痕 / R-06 停用必须真生效（**阻塞于 P1 修 jwt DISABLED 漏洞**）
