## 页面设置「背景图片」预览区与画布口径统一
- 现象：背景图透明度滑块在画布即时生效，但面板预览区是个裸 `<img>`（object-contain），完全不带 opacity / size / repeat / 页面底色。
- 改造（packages/editor/src/components/Panel/PageSettingsPanel.tsx）：
  - 预览区由 `<img>` 换成**三层叠放**：棋盘格底 → 页面背景色层（未设置时 #fff）→ 背景图 CSS 层（`background-image/size/repeat/position` + `opacity`）。这样 opacity 只作用于图片、不牵连背景色，与画布/发布页同口径。
  - 预览框按当前画布比例等比缩放（PREVIEW_MAX_W 260 / PREVIEW_MAX_H 200，最大 1:1），不再是固定 max-h-48。
  - `previewBgPosition(size)` 逐档对齐画布 `PageBackgroundImage` 的 x/y 计算：auto→left top、100%/100% auto→center top、auto 100%→left center、其余 center。
  - 裁切对话框的原图尺寸改为**离屏 `new Image()` 测量**（预览区已无可见 `<img>` 可挂 ref），`previewImgRef` 删除。
- 验证（temp/pw）：
  - `verify-bg-preview-parity.cjs`：预览 opacity 1 / 0.5 / 0.7 与 Konva 背景图节点(375×525)完全一致；预览框 112×200 符合 375:667；改尺寸→预览 `background-size` 同步(Chrome 把 `100% auto` 归一化为 `100%`)，改平铺→`repeat` 同步；残留 `<img>` 预览 0 个 → PASS。
  - `verify-crop-natural.cjs`：对话框仍拿到 natural 447×626，容器比例 0.714 = 原图比例 → PASS。
- 注意：背景尺寸/平铺用的是自定义 `BilingualSelect`（非原生 select），Playwright 必须用「按按钮文案点击」，不能 `selectOption`。

## 「退出编辑器后列表/缩略图文本错乱」根因修复（续）
- 根因（已锁死）：`packages/core/src/fonts.ts` 的 `ensureFont()` 旧实现先 `.load()` 后 `.add(ff)`（detached load），导致字体进不了 FontFaceSet，`loading`/`loadingdone` 事件永不派发；依赖该事件的「字体到位后重排版」逻辑（SchemaRenderer 的 bump、textLayout 清缓存）永远不触发 → DOM 缩略图用回退字体度量折行（错误行宽/截断）。
- 核心修复（前序会话已完成并验证）：`ensureFont` 改为「先 `fontSet.add(ff)` 再 `ff.load()`」，并新增确定性通知 `subscribeFontLoad / getFontLoadVersion / notifyFontLoad()`（每次任意 FontFace load 完成 +1）。SchemaRenderer 订阅该通知做兜底重排 + 清测量缓存。
- 本次续做（编辑器侧一致性）：编辑器画布（Konva）此前同样无「字体到位后重排」，会停在回退字体度量。
  - `packages/editor/src/components/Canvas/konvaShared.tsx`：新增 `useFontLoadEpoch()`（`useSyncExternalStore(subscribeFontLoad, getFontLoadVersion)`）。
  - `EditorCanvas.tsx`：`RenderProps` 增 `fontEpoch`；`renderElement` 三层 `<Text>`（阴影/轮廓/填充）key 改为 `` `${el.id}-*-${fontEpoch}` ``；在 `EditorCanvas` 组件内 `const fontEpoch = useFontLoadEpoch();` 并透传。字体加载→key 变化→Konva 文本节点重建→重新测量折行。
  - `KonvaElement.tsx`（离屏视频导出）同源：增 `fontEpoch` prop + 三层 Text key；`konvaVideoExport.ts` 的 `ExportStage` 调 `useFontLoadEpoch()` 并经 `buildPageChildren` 透传。

  - 实机追帧：`主段落行数序列 [8×9, 7×12]`，`document.fonts.status` 由 `loading`→`loaded` 时恰好从 8 行跳到 7 行 → 证明「字体加载前=回退字体 8 行(错)，加载后=真实字体 7 行(对)」，编辑器与列表/缩略图现一致。
