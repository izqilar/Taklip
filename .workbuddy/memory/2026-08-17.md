## 「摇摆」(swing) 画布应用仍错误 → 改用父坐标公式（彻底修复）
- 上一轮用 `getClientRect()` 绝对坐标定位旋转轴后仍不对（用户反馈"还是有误"）。**根因更深层**：`getClientRect()` 返回**绝对坐标**（含舞台/画布缩放），而 `node.position()` 设置的是**父坐标空间**；只要画布有缩放（stage scale≠1）或元素本身带旋转，`rect.x/rect.width` 与 `position` 所在坐标系不一致，旋转轴落到错误位置；且 Group 元素仍依赖 `getClientRect` 兜底不可靠。
- **最终正确做法**（konvaPlayer.ts `playSwingOnNode`）：完全不依赖 `getClientRect`。利用编辑器约定 `offset=(w/2,h/2)`、`position`=中心，故本地顶边中心 = `(offsetX, 0)`。Konva 旋转轴 = `node.position()`，于是：
  1. `offset` 设 `(ox, 0)`（ox=原 offsetX=设计宽/2），把旋转锚点从中心移到顶边中心；
  2. `position` 按 `ax = x + sin(r)·oy·sy`、`ay = y - cos(r)·oy·sy` 平移到顶边中心对应的**父坐标**（oy=原 offsetY=设计高/2，sy=scaleY）。
  推导保证变换矩阵不变（M'=M），形状起始不跳变，**任意旋转/缩放/画布缩放下都成立**。旋转分段与 hover `playSwayPivotPreview` 完全镜像（0→15→-10→5→-5→0）。

## 「摇摆」(swing) 画布仍"绕中心旋转" → 第三次修复（找到真正根因）
- 用户第三次反馈：实际应用仍是"对象中心成为摆动中心"，要求旋转轴在"对象上方边界中间"。
- **真正根因（更正前两轮的假设）**：传入 `playAnimationOnNode` 的 `node` 来自 `ComponentSettingsPanel.tsx` 的 `stage.findOne('#${el.id}')`，命中编辑器里**外层 Group**（`<Group x={cx} y={cy} rotation>` 不带 offset），其 `offset=(0,0)`、**本地原点恰好落在图形几何中心**。前两轮公式都依赖 `node.offsetX()/offsetY()`（期望 w/2、h/2）或 `node.width()`，但外层 Group 这些值是 **0** → `offset` 被设为 `(0,0)` → 旋转轴 = 该 Group 本地原点 = 图形中心 → "绕中心旋转"。这才是反复失败的本质。
- **最终正确做法**（konvaPlayer.ts `playSwingOnNode`）：不再依赖 `offsetX()/width()`。直接用 `node.getClientRect({ relativeTo: node, skipStroke, skipShadow })` 取得元素在**自身本地坐标系**的包围盒，取其顶部中心 `(localTopX, localTopY)` 作为旋转轴的本地点；再按当前旋转/缩放映到父坐标旋转轴 `pivot = curPos + R(r)·S(s)·(localTop - curOffset)`，把 `offset` 设为该本地点、`position` 设为它的父坐标位置。变换矩阵不变、形状不跳变，**对任意外层/内层 Group、任意旋转/缩放/画布缩放下都成立**。
- 三技能复核：code-reviewer 0 严重/0 一般、16 条优化（仅 L534 行长，已拆行解决）；code-bug-analyzer 确认"传入节点是外层 Group、offset=0 导致公式退化"为根因；代码简化确认 swing 函数已清晰、将长 getClientRect 行拆多行提升可读性。
- 验证：typecheck EXIT 0；dev server 5173 HTTP 200 HMR 热更新。
- **通用经验**：动画播放函数拿到的 `node` 是带 `id` 的外层 Group（offset=0），凡要"按本地几何定位旋转/缩放中心"，必须用 `getClientRect({relativeTo: node})` 取本地包围盒，绝不能信任 `node.offsetX()/offsetY()/width()/height()`（对 Group 返回 0）。同模块 `playWobble/playShake/playHeadShake` 等若也依赖这些 API 定位中心，存在同类隐患（wobble/shake 是平移为主、pivot 不敏感；headShake 用 scaleX 收窄，pivot 居中尚可；如需严格精确可一并改造）。

- 方法：逐项对账 hover 预览（presets.ts `playPreviewAnimation`）与画布通用应用（konvaPlayer.ts `playAnimationOnNode` → `computeStates`）。hover 对 exit 的转换：opacity 直接用；x/y 重写 travel（符号保留，非移出组≈size*0.95、移出组≥120）；scale 用 `amplifyEnterExitScale`（≥1→1.8，<1→0.1）；rotation 放大到 `max(160, abs)` 且保留方向；rotateX/rotateY/skewX/skewY 直接用；exit 走 `gsap.to` 单次 yoyo=false。画布通用分支用 registry 原值（computeStates：enter 把 x/y/rotation/skew 当"相对偏移"加到当前态、scale 映射到 scaleX/Y、exit 用 end=vars 原值）。
- **唯一硬 bug（已修复）**：`flipOutX/flipOutY` 的 `rotateX/rotateY` 不在 `ANIMATABLE_PROPS`，`computeStates` 直接 `continue` 丢弃 → 画布只淡出、无翻转，与 hover 的 3D 翻转折叠消失类型不一致。Konva 画布无原生 3D 旋转，在 `computeStates` 新增映射：`rotateX`→exit 时 `end.scaleY=0`（绕水平轴→垂直压扁消失）、`rotateY`→`end.scaleX=0`（绕垂直轴→水平压扁消失），旋转轴方向与 hover 的 rotateX/rotateY 一致，作为 2D 近似还原"翻转消失"。rotateX/rotateY 仅 flipOutX/Y 使用（出场区），入场区无 flipIn，映射安全。
- **其余 38 个效果**：类型与方向与 hover 一致（位移方向、旋转方向、skew、scale 放大/缩小方向、opacity 淡出均对齐）。幅度差异（rotation 未放大到 160、scale 未 amplify 到 0.1/1.8、位移用 registry 真实值而非 hover 的归一化 travel）属"演示夸张化 vs 应用真实值"的既有设计约定，且画布用 registry 原值反而更贴合 animate.css 原版（如 zoomOutDown 画布 scale 0.5 即原版、hover 夸张到 0.1）；故未改动——否则旋转/缩放会被过度放大失真。

## 「向下淡出」画布方向反转 bug（19:55）
- 现象："向下淡出"(fadeOutDown) 画布实际应用方向反了（实际向上淡出）。根因：`computeStates` 的 exit 分支原只写 `end[key] = value`，把 registry 的 x/y/rotation/skew 当成了 Konva 绝对坐标；但 registry 这些值沿用 GSAP 相对偏移语义（`y:60`=相对当前向下 60px）。入场(enter)分支已正确做 `start=current+value`，出场(exit)分支漏了 → `fadeOutDown` 的 `y:60` 被解释为绝对 y=60（画布顶附近）→ 向上飞、淡出。slideOut* 因幅值 ±450/±750 远超画布才碰巧方向正确。
- 修复：exit 分支改为与 enter 对称——x/y/rotation/skew 用 `end=current+value`（相对偏移→绝对坐标），opacity/scale 仍取绝对值。一并修正了所有出场位移/旋转类动画（fadeOut/rotateOut/rollOut/lightSpeedOut 等）的方向一致性潜在问题；flipOut 的 rotateX/rotateY→scale 压扁、scale 映射均 `continue` 不受影响。
