### 关键决策 / 踩坑
1. **分组从「中文标签作 map key」改为「英文常量 + i18n 兜底」**：原 `group: '系统'` 这种字符串既不能 i18n 也不能保证显示一致性。新 `MenuGroupKey` 联合类型 + `GROUP_ORDER` 数组 + `GROUP_LABEL` 默认值 + `t('group.<key>', GROUP_LABEL[key])` 是更稳的范式。
2. **分组顺序用显式 `GROUP_ORDER` 而非 Map 插入顺序**：声明顺序副作用太脆弱，新增条目可能改变老分组的相对位置；显式数组让分组顺序与数据声明解耦。
3. **分组标题栏字号故意与二级菜单一致（13.5px）**：用户明确要求「与二级菜单名称的字体一样大小」，层级区分靠**字重 + 底色 + 左竖条 + 字号一致**的复合手法，而非把字号做大。
4. **折叠态用 localStorage 而非 sessionStorage**：分组折叠是用户的「工作台布局偏好」，跨刷新保留更友好；按视角（console/agent/provider/user）分别 key，互不干扰。
5. **路由命中被折叠分组自动展开**：分组折叠后用户点击其他分组内的菜单，路由跳转会让被点击项所在的分组展开——避免「我刚点的菜单怎么不见了」的体验事故。`useEffect` 只依赖 `location.pathname + view`，避免循环。
6. **折叠时汇总待办气泡**：把分组内所有菜单的待办数累加，折叠态仍能看到该组的待处理量（实测：评价与反馈 = 消息中心 1 + 反馈 10 = 11）。
7. **数据基线复位**：之前 `verify-badge-render` 偶发飘红是因为前几轮的 `smoke-provider-review` / `smoke-agent-modals` 通过真实接口改了 `providerStatus` 与 `template.status`；新增 `reset-badge-baseline.mjs` 按 `e2e_` 前缀复位为种子状态，从此 `verify-badge-render` 每次都跑在同一条起跑线上。
8. **选择器要按 `data-group` / `data-menu` / `data-collapsed` 锁定**：之前用「父 .lbl 的父 div」推断菜单容器，遇到折叠后隐藏的菜单会让选择器链断裂。给菜单项和分组标题栏加上 `data-*` 属性，校验脚本就更稳。

### 报告的 bug
- 审核对话框：填写审核意见（或直接点击）后弹窗"破窗"——字段全消失，三个按钮无反应、无法返回工作台。

### 根因（两层叠加）
1. **状态机遗漏**：`const close = () => setCurrent(null)` 只清 `current`，没清 `mode`，导致 `<Modal open={mode === 'ok' || mode === 'no'}>` 仍在 `open` 态但 `current === null` → 字段变 undefined → 按钮全部不响应。
2. **AntD Modal 卸载语义**：v5 默认保留已关闭 Modal 的 children，`<Modal open={false}>` 后 `.ant-modal-content` 仍挂载在 DOM（实测 `.ant-modal-content` 计数 ≥ 1）。`destroyOnClose` 已废弃 → 改用 v5.25+ 新增的 `destroyOnHidden`，关闭后真正卸载节点。

### 关键决策 / 踩坑
1. **`<Modal destroyOnHidden>` 不是可选项，是关闭语义正确的必要条件**：v5 默认 children 持久化会留下「按钮没了但节点在 DOM」的死状态 —— 单改 state 永远不够，DOM 也要真正卸载。`destroyOnClose` 已废弃会触发 5 条 console.error warning（冒烟脚本会记为失败），用 `destroyOnHidden` 一次到位。
2. **`open` 表达式加 `current != null` 防御**：`mode` 和 `current` 是两个独立 state，只要有一次不同步（如某次重构忘了清 mode），就会有「破窗」。让 `open` 表达式**自描述可用性**，比依赖 useEffect 同步更稳。
3. **编辑理由要走「前端 + DTO + 服务端校验 + 审计日志」全链路**：仅前端校验会被 curl 绕过；仅服务端校验体验差；审计日志先落到 stdout 不引入新表，不破坏现有数据模型。
